# Spektramat 对齐 spektrafilm 的完整算法修改计划

## 目标和边界

目标是把 Spektramat 的照片处理链路改成 spektrafilm 的完整运行时语义：拍照后的照片、RAW/JPEG 导入、暗房预览、片库缩略图、重新冲印、片边/日期 proof 和最终导出都走完整算法；原计划只有视频录制允许使用 LUT。**后续经用户确认，手机拍摄前取景也允许使用独立 GPU LUT，见 [GPU 实时预览记录](相机GPU实时预览-2026-11-12.zh-CN.md)。下文保留原计划作为历史基线。**

这里的“完整算法”包含：输入色彩空间和 CCTF、Hanatos/Mallett 光谱上采样、自动曝光、UV/IR 滤镜、高光保护、相机/放大机 diffusion 和 lens blur、halation、DIR、颗粒、精确光谱印相、相纸显影、预闪、扫描积分、black/white correction、glare、scanner blur/unsharp、输出色域压缩和 CCTF。

需要明确一个物理限制：静态 3D LUT 不能表达自动曝光、halation、DIR 空间扩散、颗粒、glare、unsharp 和任何依赖邻域、随机数或整幅图统计的运算。因此视频的“完整胶片转换 LUT”定义为完整的**逐像素部分**：输入色彩变换 → RGB-to-raw → 胶片曲线/DIR 点运算 → 精确印相积分的 LUT 近似 → 相纸曲线 → 精确扫描积分的 LUT 近似 → 输出色域/CCTF。视频的空间和随机效果若要保留，必须作为独立实时 GPU pass；不能把它们虚假地塞进 3D LUT。若选择“视频只允许 LUT、不要额外 pass”，则视频明确关闭这些不可表达的效果，并在 UI 中标注该限制。

## 处理模式和路由规则

新增明确的 `RenderMode`，禁止调用方通过“是否有 preview 参数”等隐式条件选择算法：

| 模式 | 用途 | 印相/扫描 | 空间/随机效果 | LUT |
|---|---|---|---|---|
| `PHOTO_FULL` | RAW/JPEG 拍照成片、照片导入、暗房 proof、片库缩略图、重新冲印、Sony 收片后的照片处理 | 81 波长逐像素积分 | 完整执行 | 禁止 |
| `PHOTO_PREVIEW_FULL` | 相机拍照取景、暗房交互预览、监视器非录制预览 | 81 波长逐像素积分，降低分辨率并异步执行 | 完整执行；可按预览尺寸缩放空间核 | 禁止 |
| `VIDEO_LUT` | 视频编码输出 | 视频专用完整逐像素 LUT | LUT 之外用实时 GPU pass，或按产品选择关闭 | 允许且必须使用 |

必须增加路由断言：照片路径遇到 `renderFast`、`tables.enlarger`、`tables.scan` 或任何 `use_*_lut` 都直接报错；只有 `CameraFilm` 的 `VIDEO_CAPTURE` 输出可以请求 `VIDEO_LUT`。视频 LUT 不应被相机拍照、JPEG capture、RAW capture、`Printer`、`Library` 或 `DarkroomState` 复用。

## 第一阶段：建立与 spektrafilm 对齐的参数契约

### 1. 将 `RenderParams` 从 Android 专用扁平结构扩展为 reference 参数树

保留旧字段作为迁移层，但内部使用与 `RuntimePhotoParams` 对应的结构：

- `camera`：`exposure_compensation_ev`、`auto_exposure`、`auto_exposure_method`、`film_format_mm`、`filter_uv`、`filter_ir`、`lens_blur_um`、`diffusion_filter`。
- `film_render.halation`：scatter/halation amount、spatial scale、core/tail、tail weight、boost/protect、bounce、renormalize。
- `film_render.dir_couplers`：amount、两个 inhibition、全部 gamma、diffusion size、tail size、tail weight。
- `film_render.grain`：active、sublayers、particle area、通道/层 scale、density min、uniformity、blur、dye cloud blur、micro structure、`n_sub_layers`、seed/sampler。
- `enlarger`：illuminant、print exposure、compensation、normalize、C/M/Y neutral、Y/M/C shifts、lens blur、diffusion、preflash。
- `print_render`：glare 全参数和 `density_curves_morph`。
- `scanner`：lens blur、black/white correction、levels、unsharp sigma/amount。
- `io`：input/output color space、CCTF decode/encode、input/output gamut compression、scan_film、geometry。
- `settings/debug`：`rgb_to_raw_method`、Hanatos adaptation、`lut_mode`、spatial/stochastic switches、LUT resolution。

JNI 不再使用当前 `jlook` 的 14 个位置参数作为唯一协议；改成版本化 JSON/ByteBuffer 参数或明确的 native request struct。旧 recipe 读取后转换成新参数树，并对越界 DIR amount 做迁移钳制和日志记录。

### 2. 统一曝光语义

- 照片完整路径保留 reference 的自动曝光方法和测光色彩空间；不要在 `lt_jni.cpp` 中无条件设置 `p.auto_exposure=false`。
- `meteredEv` 只作为 UI/缓存结果，不能与引擎自动曝光重复相乘。每张照片建立“原始输入 + 测光输入参数 + EV”快照，重新处理时按 reference 规则重算或明确复用同一快照。
- 明确产品默认与 reference 默认：reference 的 `print_exposure_compensation=true`；若 Android 产品继续采用 SpektraLab 的 `false`，必须作为显式 product profile，而不是隐藏在 JNI 中。
- 视频 `lut_mode` 关闭 auto exposure、曝光补偿、print compensation、image-global highlight boost 和 scanner black/white/unsharp，再按固定视频曝光建立 LUT；视频录制期间不得因为画面内容变化而重建出不同的隐式曝光。

## 第二阶段：补齐完整胶片曝光与显影

### 1. 输入色彩和 RGB-to-raw

在 Android 解码边界保存源 ICC/色域信息，将输入转换到 reference 约定的工作空间，不再把所有非 RAW 输入直接当作 sRGB。实现：

- sRGB、Display P3、Adobe RGB、ProPhoto RGB 的矩阵/CCTF decode；
- `input_cctf_decoding`；
- Hanatos 2025 的 adaptation window/surface/spectral Gaussian blur；
- Mallett 2019 选择；
- input gamut compression；
- `nan_to_num`、负值和域外输入与 Python 规则一致。

### 2. 相机滤镜和曝光前处理

按 spektrafilm `FilmingStage.expose()` 的顺序实现：

1. RGB-to-raw；
2. exposure compensation；
3. highlight boost/protect；
4. UV/IR band-pass filter 和灵敏度归一化；
5. camera diffusion filter；
6. camera lens blur；
7. halation/scatter；
8. color reference filming correction；
9. `log10`。

所有空间核使用与 reference 相同的像素尺寸、边界、归一化和 PSF；不能继续使用当前 C++ 常量覆盖可调参数。

### 3. DIR 和曲线

- 从 profile/参数加载完整 DIR matrix 和 inhibition，而不是在 `dir_couplers_matrix()` 中只按 stock 硬编码。
- 实现 `density_curve_gamma`。
- 精确复制 reference 的 `compute_exposure_correction_dir_couplers` 顺序、正片负片方向、Gaussian + exponential tail 拟合和边界行为。
- UI、JSON、JNI、C++ 四层统一 amount 范围；默认拒绝 >1.5，旧配方读入时钳制并记录迁移。

### 4. 颗粒

- 按 profile 参数支持 `n_sub_layers`，不要固定三层。
- 对齐 Poisson/binomial sampler、uniformity、density min、particle blur、dye clouds、micro structure 和 seed 语义。
- 明确 `grain_sampler=exact/stochastic`；照片 full 默认使用 reference stochastic 语义，测试按统计分布和 seed 复现规则验收。
- `grain_amount` 若保留，作为 reference 参数外的产品层混合，默认照片算法关闭该额外混合或把它映射成 reference 的等价参数，避免双重混合。

## 第三阶段：把照片印相改为精确光谱积分

### 1. 新增 exact spectral print kernel

在 `spektra_engine.cpp` 中保留 `build_spectral_lut()` 供视频 LUT baker 使用，同时新增照片专用的逐像素函数：

```text
film CMY density + base density
  -> density_spectral[81]
  -> filtered enlarger illuminant
  -> density_to_light
  -> paper sensitivity dot product
  -> midgray geometric-mean factor
  -> optional preflash
  -> enlarger diffusion/lens blur
  -> log10
```

该函数必须支持 NaN profile 数据、负片/正片 density、TH-KG3 以外的 illuminant、中性滤镜数据库、print exposure compensation 和 normalize 的全部组合。照片路径不得调用 `PrintSetup.enlarger.sample()`。

### 2. 对齐 reference 的打印校正

- 实现 `ColorReferenceService` 的 film black/white、print black/white 和 midgray 校正；不要只保留当前 C++ 的单一 midgray factor。
- 实现 `preflash_exposure`、preflash Y/M shift 和 base density preflash。
- 实现 enlarger lens blur、diffusion filter。
- 实现 `density_curves_morph` 和 profile type 的 print develop。
- 支持数据库中性滤镜的动态选择和缺失项警告。

## 第四阶段：把照片扫描改为精确光谱积分和完整输出

### 1. 新增 exact spectral scan kernel

照片路径逐像素执行：

```text
print/film CMY density + base density
  -> density_spectral[81]
  -> viewing illuminant
  -> density_to_light
  -> CIE 1931 CMF
  -> Y normalization
  -> black/white XYZ correction
  -> glare
  -> XYZ -> requested output RGB
  -> output gamut compression
  -> scanner lens blur / unsharp
  -> requested CCTF
```

直接扫底片和相纸扫描都走同一 exact kernel，只替换 profile、base density 和 viewing illuminant。不得在照片路径访问 41³ scanner LUT。

### 2. 输出和后处理

- 支持 sRGB、Display P3、Adobe RGB、ProPhoto RGB、16-bit 浮点/整数输出；JPEG 只是最后的编码格式。
- 支持 `output_cctf_encoding`。
- 支持 output gamut compression 的算法和参数；只有显式选择 clip 时才 clip。
- 支持 scanner lens blur、white/black correction、levels、glare percent/roughness/blur、unsharp sigma/amount。
- 保持 full float 到最后一步；不能在引擎内部提前转 RGBA8 再做 gamut/锐化。

## 第五阶段：视频专用完整 LUT

### 1. LUT 的边界

新增独立 `VideoLut`/`VideoLutBaker`，不能复用照片 `FilmTables` 的简化 tc/curve/print/scan 组合。LUT bake 使用 reference 的 `debug.lut_mode` 语义：关闭 auto exposure、空间效果、随机效果、highlight boost、scanner black/white/unsharp 和 image-global correction，但把以下逐像素步骤完整烘焙进去：

- 输入色彩空间/CCTF；
- Hanatos 或选定 RGB-to-raw 方法；
- 胶片 exposure、density curve、DIR pointwise matrix、正片/负片方向；
- 精确印相积分的采样结果；
- 相纸显影曲线/morph；
- 精确扫描积分的采样结果；
- output gamut compression 和 CCTF encode。

LUT 采用 shaper + 3D lattice（建议至少 65³，极端高光使用扩展域或 log shaper），保存输入/输出色域、film/paper、filters、exposure、neutral filters、资产版本、spektrafilm commit、LUT 分辨率和 SHA-256。LUT 域外行为必须与 reference 的 gamut/exposure 规则一致，禁止简单 clamp。

### 2. 视频运行时

- 视频录制开始时固定一个完整 `VideoLutKey`，异步 bake 并原子替换；录制过程中参数改变时要么重建并在帧边界切换，要么禁止改变会影响 LUT 的参数。
- 视频 GPU pass 仅负责 LUT 以外的实时 spatial/stochastic 效果：halation/scatter、DIR diffusion、grain、glare、unsharp。若设备性能不足，按明确的 video preset 关闭这些 pass；不能退回照片 LUT 或旧 `latent.glsl` 简化组合而不告知。
- `CameraFilm.paint()` 按输出 target 判断：只有 `VIDEO_CAPTURE` 使用 `VIDEO_LUT`；照片 capture 和非录制 viewfinder 不得调用 LUT。
- 视频预览如果不是正在录制，也不自动获得视频 LUT 权限；使用 `PHOTO_PREVIEW_FULL` 的低分辨率 exact path，或明确标记为 video preview。

## 第六阶段：Android 路由改造

需要逐一修改并加断言：

| 文件/路径 | 修改 |
|---|---|
| `engine/src/main/cpp/spektra_engine.cpp` | exact print/scan、完整参数、reference color reference；LUT 仅供 VideoLutBaker |
| `spektra_engine.hpp` | 新参数树、RenderMode、输出色彩空间和 exact/video API |
| `lt_jni.cpp` | 删除无条件 `p.auto_exposure=false`；增加版本化完整 request；照片调用 exact；视频调用 VideoLut |
| `lt_tables.cpp/.hpp` | 限制为视频 LUT/资产服务，不再给照片 full/preview 提供 enlarger/scanner 表 |
| `lt_fast.cpp/.hpp`、`latent.glsl` | 标记为 video-only；禁止 `Library`、`PrintDesk`、暗房照片 proof 调用 |
| `Printer.kt` | 保持 full engine，但切换到 exact photo mode，并传完整 params |
| `DarkroomState.kt` | proof 使用 exact reduced-size engine，支持取消、缓存和 source negative reuse |
| `Library.kt` | 缩略图不用 `renderFast`；使用 exact photo preview/full engine 的缩小结果 |
| `PrintDesk.kt` | 不再使用 fast tables 生成照片结果 |
| `CameraFilm.kt` | 仅 VIDEO_CAPTURE 使用 VideoLut；照片 capture 走原图/RAW + `FilmEngine.develop` |
| `Monitor.kt` | 非录制监视器不再默认使用 LUT；使用 exact reduced preview 或明确 video-preview 模式 |
| `Decoder.kt` | 保留源色域/ICC/RAW 元数据，传给完整 pipeline |
| `Look.kt`、`Recipes.kt` | 扩展参数、旧配方迁移、版本号和默认值记录 |

照片 full engine 应保留 negative cache：胶片参数不变时缓存 `cmy_film`，只重新执行 exact print/scan；印相滑块不应重新跑整幅胶片显影。缓存 key 必须包含 profile、输入色域、曝光、所有空间参数、seed 和 geometry。

## 第七阶段：资产和构建系统

1. 从指定 spektrafilm commit 重新生成并提交 81 波长 profiles、illuminants、CMFs、neutral filters、ICC/色彩空间矩阵、Hanatos adaptation 数据和 gamut compression 表。
2. 资产包写入版本 manifest：上游 commit、生成脚本 hash、波长轴 hash、profile hash、CMF/illuminant hash。
3. 视频 LUT 与 exact photo engine 共用同一资产 manifest；禁止手工导出一套“看起来相近”的 LUT。
4. Android ABI 需要同时支持 CPU exact kernel 和 GPU video LUT；启动时检查 manifest，不匹配则拒绝渲染并给出可诊断错误。

## 第八阶段：验证计划

### 1. 参考 parity

把 spektrafilm Python 作为 oracle，比较每个 tap，而不是只比较最终 JPEG：

- `rgb_pre`、`log_e_film`、`cmy_film`、`log_e_print`、`cmy_print`、`rgb_out_linear`、encoded output；
- 逐像素 float 误差、p50/p95/p99/max、负值/NaN 计数；
- 81 波长资产、profile、参数 JSON、seed 和输入图哈希全部记录。

### 2. 必测参数矩阵

- 25 款胶片 × 9 款相纸、正片/负片、黑白/CineStill；
- sRGB/Display P3/Adobe RGB/ProPhoto；CCTF 开关；广色域和负值输入；
- auto exposure 方法、EV、UV/IR、highlight boost、camera/enlarger diffusion/lens blur；
- DIR amount=0、1、1.5，>1.5 必须拒绝；不同 inhibition/gamma；
- grain exact/stochastic、不同 `n_sub_layers` 和 seed；
- halation/scatter 参数、preflash、print morph、glare、black/white correction、unsharp；
- scan_film、输出色域、output gamut compression、CCTF；
- 有/无片边、日期、裁切和旋转。

### 3. 路由与 LUT 验证

- 照片路径静态扫描和运行时断言：不能调用任何 enlarger/scanner LUT。
- 视频路径必须调用 VideoLut，且 LUT metadata 与当前 params 完全匹配。
- 随机采样 LUT cube 点，与同参数 exact pointwise oracle 比较；目标误差按 float 和 8/10-bit 输出分别制定。
- 改变 LUT 不支持的空间参数时，必须触发独立 GPU pass 或拒绝变更，不能静默得到旧 LUT。
- 预览、拍照成片和最终导出分别做金样图，证明照片路径不会退回 fast shader。

### 4. 性能和内存

- 在低端、中端、高端 Android 上测试 exact full、exact reduced preview、video LUT 三档吞吐、延迟、峰值内存、取消响应。
- 用 negative cache、分块处理和 81 波长 SIMD/线程并行控制照片 full 成片成本；不得用降低算法精度代替优化。
- 视频 LUT bake 必须在录制前完成或使用上一版兼容 LUT；录制过程中不能阻塞编码线程。

## 实施顺序和交付物

### M0：契约冻结

交付 `RenderMode`、完整参数 schema、资产 manifest、旧 recipe 迁移规则、tap/parity JSON 格式和路由断言。此阶段不改变成片观感。

### M1：exact spectral core

交付逐像素 81 波长印相/扫描、color reference、输出色域/CCTF；先以现有固定参数复现旧结果，再与 Python oracle 对齐。此阶段禁止照片使用 LUT。

### M2：完整参数和空间/随机模型

交付 filters、boost、diffusion、lens blur、halation、DIR、grain、preflash、print morph、scanner correction。每个参数都要有 tap parity 和边界测试。

### M3：照片全链路切换

交付 `PHOTO_FULL`/`PHOTO_PREVIEW_FULL` 路由，替换 `Library`、`PrintDesk`、`DarkroomState`、`Printer`、照片 capture 和非录制 monitor 的 fast 调用；完成旧 look/recipe 迁移。

### M4：视频 LUT

交付独立 VideoLut baker、shaper+3D LUT 资产、metadata/cache、视频 GPU pass 和 `CameraFilm` 的 VIDEO_CAPTURE 路由。加入 LUT fidelity 和录制稳定性测试。

### M5：删除旧照片 fast 入口

在所有 parity 和真机测试通过后，将 `renderFast`、旧 `latent.glsl` 的照片调用删除或编译期限制为 video-only；保留代码也必须由 API 类型系统阻止照片调用。

## 验收标准

1. 任意照片导入、拍照、暗房处理、缩略图、proof 和导出日志都显示 `PHOTO_FULL` 或 `PHOTO_PREVIEW_FULL`，没有 LUT 命中。
2. 视频录制日志显示 `VIDEO_LUT`，LUT metadata 与当前 look/asset manifest 匹配。
3. 照片 full path 与 spektrafilm Python 在所有必测 tap 上达到约定 float 误差；不能只以 8-bit JPEG 相等作为通过。
4. 41³ LUT 只存在于视频资产或显式视频缓存中；照片 exact path 不构建、不读取 enlarger/scanner LUT。
5. 对无法由静态 LUT 表达的 spatial/stochastic/global 操作，在视频中有独立 GPU pass 或明确关闭状态，不能默默丢失。

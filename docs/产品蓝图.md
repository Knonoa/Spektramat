# 潜影 Latent：产品蓝图

「潜影」是胶片曝光之后、显影之前留在乳剂里的那张看不见的影像。这个 App 做的就是这件事：
把手机或相机拍到的数字影像，当作落在胶片上的光，按 spektrafilm 的光谱模型曝光、冲洗、印相，得到成片。

名字和包名（`com.spektra.latent`）是工作代号，改起来只动两处。

## 1. 一句话定义

一台装在手机里的胶片工作站：**拍 → 存 → 冲 → 印** 一条线走到底，每一步都对应胶片的真实流程，
而且每一步都流畅、看得见、可以回头改。

## 2. 用户走的路

```
        ┌── 相机（手机镜头，胶片取景，照片/视频）
拍 ─────┤
        └── 联机（USB 连接相机，实时取景，遥控拍照/录像）
                         │ 原片永远保留
                         ▼
存 ──── 片库：一卷一卷的底片（导入的照片也在这里）
                         │ 点开一张
                         ▼
冲 ──── 暗房：原片 → 胶片 → 印相 → 整饰     （顺序就是光走过的顺序）
                         │ 点「冲印」
                         ▼
印 ──── 后台冲印（屏幕一角的小指示循环到完成，不占页面）→ 成片存入相册，同时挂在这张底片名下
```

三条规则贯穿全程：

1. **原片不动。** 导入、拍摄、联机接收的文件原样存进 App 的片库；所有调整只是一份参数。
2. **看到的就是冲出来的。** 预览和成片用同一套胶片数据；预览省掉的只有肉眼在屏幕上看不出的微小项，并且写明是哪些。
3. **设备有什么就给什么。** 镜头、手动参数、RAW、录像规格都按设备实际报告的能力显示，没有的不摆出来。

## 3. 四个地方

**片库是首页**。相机和联机是从片库底部走进去的全屏场所，用完回到片库；暗房不是入口，是从一张底片走进去的房间
（从相机里点刚拍的那张进暗房，退出时回到相机）。

### 3.1 片库

- 按「卷」组织：一次导入、一次拍摄、一场联机各成一卷，卷名默认是日期，可改。
- 一卷展开是印样（接触印相）式的网格：缩略图显示当前冲洗效果，下方是片边式的帧号。
- 导入：系统相册多选、文件管理器（RAW）、其他 App 的「分享到 / 打开方式」。导入即复制进片库，之后不依赖原位置。
- 点一张进入看片：左右滑动换张、双指放大、打星、按住看原片；从这里进暗房。
- 每张底片下面挂着它冲印过的成片（哪天、哪款胶片、多大），可以再次分享或删除。
- 多选后可以：批量套用配方并冲印、移到另一卷、删除。

### 3.2 暗房（调色）

画面在上，下面一条「工序轨」，从左到右就是算法的顺序。点一个工序，下面换成它的控制项。

| 工序 | 它在算法里的位置 | 控制项 |
| --- | --- | --- |
| **原片** | 胶片之前，作用于场景光 | 曝光、色温、色调、高光、阴影、白色、黑色、自然饱和度、饱和度、暗角校正（之后：HSL、降噪、镜头校正） |
| **胶片** | 曝光与显影 | 胶片型号、增感/减感、光晕、颗粒、层间效应 |
| **印相** | 放大机与相纸，或直接扫描底片 | 相纸、印相曝光、黄/品红滤色、眩光 |
| **整饰** | 成片之后 | 曲线、色彩分级、暗角、锐化、片边、日期（第三阶段） |
| **构图** | 几何 | 裁切、旋转、拉直、翻转（第三阶段） |

- 滑杆是一把刻度尺：横向拖动，带齿感震动，双击归零，数值用片边字体显示。
- 拖动时画面 60 帧实时变化（GPU），不出现「草稿 → 清晰」的跳变。
- 按住画面看原片；撤销/重做；参数自动保存，退出再进来还在。
- 「看底片」（第三阶段）：在胶片工序里可以切到底片本身的样子（橙色片基的负像），这是模型里真实存在的中间结果。
- 配方（第三阶段）：把「胶片 + 印相 + 整饰」存成配方，可套用到别的照片和相机。原片工序的校正属于这张照片，不进配方。

### 3.3 相机

- **取景**：实时胶片效果，和暗房是同一份胶片数据、同一段着色器。顶部是相机里装的那卷胶片，点它换卷。
  界面锁定竖屏；照片和视频按手机实际握持的方向保存。
- **镜头**：两种手机都认。新手机把几颗镜头合成一个「逻辑相机」，靠变焦比切换——变焦范围低于 1 的一端就是超广角，
  长焦从它的物理镜头的焦距算出来；老手机和部分厂商把每颗镜头列成单独的相机——按它和主摄的视角比例命名（0.6 / 1 / 3）。
  没有长焦的手机给一个 2（主摄中心裁切）。厂商不对第三方开放的镜头系统不会列出来，这里也就不显示。双指可以连续变焦。
- **设置**：只显示这颗镜头自己报告支持的项——曝光补偿、感光度、快门、对焦、白平衡预设、RAW。
  感光度和快门的刻度尺按档位走（每格 1/3 档），读数是相机上的写法（ISO 125、1/60）；自动时显示相机当前实际用的值。
  感光度和快门动了任何一个，两个一起变成手动（相机的曝光要么自动要么手动），旁边的「自动」一点就回去。
- **照片**：拍下的是原片（JPEG，或设备支持时的 RAW/DNG），按天收进片库里「相机 日期」这一卷，带着当时装的胶片作为冲洗方式，
  之后在暗房可以随便换。JPEG 的明暗是相机和人已经决定好的，原样接收；RAW 和别的 RAW 一样测光，拍摄时拨的曝光补偿记在这张的「曝光」里。
  左下角是刚拍的一张，点开直接进暗房。
- **视频**：胶片效果直接录进画面（视频没有事后的暗房）。画质 1080P / 720P / 480P、帧率按设备支持列出；存进相册 `Movies/Latent`。
  有麦克风权限就带声音，没有就无声并标出来。
- **出错时**：系统相机服务崩溃或被占用后，相机自己重新识别镜头并恢复取景，不用退出 App。
- 还没有的：取景和视频里没有光晕（它需要多一遍模糊，照片冲印时才加）；4K 视频（逐帧过胶片，要先在真机上量过性能）；闪光灯；画幅框（135、6×6、XPan）。

### 3.4 联机

- USB 连接相机（PTP）。连上后显示型号、可用能力。
- 实时取景叠加胶片效果；遥控快门；相机里新拍的照片自动收进当前这一卷。
- 录像：把带胶片效果的实时画面录成 MP4；相机支持时同时触发机身录像。
- 断线不丢片：已收到的原片先落盘再登记，重连不重复收。

## 4. 冲印指示

冲印在后台进行，不占任何页面：点了「冲印」之后可以接着调、换一张、回片库，多张依次排队。
告诉人「正在冲」的是一个加载指示，不是一场演出——小、快、一直循环到完成。

- **位置**：顶栏下方靠右的一块 56dp 小方片，每个页面都在同一处。不放在屏幕正中，因为正中是看画面的地方；
  它紧挨着「冲印」按钮，点完按钮视线本来就在那里。除了它自己，不拦任何触摸。
- **内容**：这张照片本身，缩成 5×5 的大像素。一道波从左上扫到右下，扫到的像素张开成胶片的三层染料
  （黄、品红、青，和乳剂里的上下顺序一致），再合上变成冲洗后的颜色；下一道波把它带回原片，循环没有接缝。
  一趟 0.85 秒。
- **进度**：方片外圈的琥珀色线跟着引擎真实的阶段走（读取、曝光、显影、印相、扫描、保存）。
- **完成**：大像素分几步变细，直到就是成片，方片略微变大并震动一下。点开是带相纸白边的成片，可以分享；
  不点，5 秒后自己收起（成片已经在相册里）。
- **点开进行中的方片**：看到是哪一张、到了哪一步，可以停止；停止不留下任何文件。
- **失败**：外圈变红并留在原处，点开说明原因。

## 5. 视觉与手感

- **中性的暗环境。** 照片周围是不带色偏的黑和灰（判断颜色需要中性的环境），界面本身不抢画面。
- **一种强调色：安全灯琥珀 `#F2A93B`。** 只用在「当前值、当前工序、进度」。红色 `#E5484D` 只给录制和删除。
- **片边字体。** 所有数值、帧号、胶片名用窄体无衬线（TeX Gyre Heros Condensed），和胶片片边上印的字是一路；中文用系统字体。
- **刻度尺** 是唯一的调节控件，全 App 一致。
- **动效只回应操作**：进暗房时缩略图长成大图；换工序时控制区横移。唯一自己在动的东西是冲印指示，而它很小。

色板：幕布 `#0C0C0C`、机身 `#161616`、刻线 `#2B2B2B`、次要文字 `#8A8A8A`、主文字 `#EDEDED`、琥珀 `#F2A93B`、相纸白 `#F1EEE6`（只用于成片的白边）。

## 6. 技术结构

```
Latent/
  engine/   C++：spektrafilm 胶片引擎、RAW 解码（内置 + LibRaw）、调色算法；JNI；胶片数据 engine.bin
  app/      Kotlin + Jetpack Compose：界面、片库（数据库）、GPU 渲染管线、相机、联机
  docs/     本文件
```

- **胶片引擎**沿用 2.0 里那份逐阶段对照 spektrafilm 移植的 C++（它本身就是算法，不是界面），不重写。
- **实时预览走 GPU**：调色（片元着色器）→ 光谱曝光表 → 特性曲线 + 层间效应 → 底片密度 → 印相/扫描表 → 屏幕。
  这些表由 CPU 引擎按当前胶片/相纸/滤色现算出来，所以 GPU 画面和 CPU 成片出自同一份数据。
- **成片走 CPU 引擎**：全尺寸、全部空间效应（光晕、颗粒、层间扩散、眩光、锐化）。
- **调色算法只写一份**：同一个文件既编译成着色器，也编译成 C++，预览和成片不会各算各的。
- **片库用数据库**（事务、崩溃不丢），原片与缩略图在 App 私有目录，成片写进系统相册 `Pictures/Latent`。

## 7. 分期

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 一 | 主线：片库（导入）→ 暗房（原片/胶片/印相，GPU 实时）→ 后台冲印 → 成片 | 已通，模拟器上验证过 |
| 二 | 相机：胶片取景、镜头识别、手动参数、RAW、视频 | 已通，模拟器上验证过（RAW 写文件除外，见下）；真机未测 |
| 三 | 调色补全：曲线、HSL、色彩分级、局部对比、裁切、配方、历史、批量 | 未开始 |
| 四 | 联机：USB 接收、实时取景、遥控快门、录像 | 未开始 |
| 五 | 打磨：真机适配、性能、16 位与广色域输出、平板与折叠屏 | 未开始 |

真机相关的部分（各家手机的镜头与手动能力、各家相机的联机协议）只能在真机上验收；模拟器上能验证的会写明是在模拟器上验证的。

相机在模拟器上验证到哪一步：

| 项目 | Android 12 模拟器 | Android 16 模拟器 |
| --- | --- | --- |
| 胶片取景、换卷、镜头档位、曝光补偿、白平衡 | 通过 | 通过 |
| 拍 JPEG 进片库、从相机进暗房 | 这个镜像的相机驱动一压 JPEG 就崩溃（任何 App 都一样），无法验证 | 通过 |
| 手动感光度 / 快门 | 它的相机不支持，界面不显示这两项 | 前置相机支持，拨动后画面明暗跟着变 |
| RAW | 不支持，界面不显示 | 取景和拍摄通过；写 DNG 时系统报缺少元数据（模拟相机不给），文件没写成 |
| 录像（胶片效果在画面里） | 通过，720×1280，文件可播放 | 未单独再测 |
| 相机服务崩溃后自动恢复 | 通过 | — |

模拟器用 CPU 模拟 GPU，取景和录像每秒只有几帧；真机上的帧率、多镜头手机的档位、RAW 文件，都要在真机上看。

# Spektramat：产品蓝图

这个 App 把手机或相机拍到的数字影像，当作落在胶片上的光，按 spektrafilm 的光谱模型曝光、冲洗、印相，得到成片。

名字里的 Spektra 来自 spektrafilm；`-mat` 是胶片时代机器的叫法（Focomat 放大机、Instamatic 相机、Fotomat 冲印亭）：
一台装在口袋里的冲印机。名字只有这一个，没有中文名。

包名（`com.spektra.latent`）和代码里的 latent 是早期的工作代号（潜影：胶片曝光之后、显影之前留在乳剂里的那张看不见的影像），
保留不动；App 对外的名字在 `strings.xml` 的 `app_name` 和 `LatentApp.kt` 的 `APP_NAME` 两处。

## 1. 一句话定义

一台装在手机里的胶片工作站：**拍 → 存 → 冲 → 印** 一条线走到底，每一步都对应胶片的真实流程，
而且每一步都流畅、看得见、可以回头改。

## 2. 用户走的路

```
        ┌── 相机（手机镜头，胶片取景，照片/视频）
拍 ─────┤
        └── 监视器（USB 连接相机，实时取景，遥控快门，监看录制）
                         │ 原片永远保留
                         ▼
存 ──── 片库：一卷一卷的底片（导入的照片也在这里）
                         │ 点开一张
                         ▼
冲 ──── 暗房：原片 → 胶片 → 片边 → 印相 → 整饰     （顺序就是光走过的顺序）
                         │ 点「冲印」
                         ▼
印 ──── 后台冲印（屏幕一角的小指示循环到完成，不占页面）→ 成片存入相册，同时挂在这张底片名下
                         │
看 ──── 观片台：把底片摊在灯箱上，摆放、比较、用放大镜看细节
```

三条规则贯穿全程：

1. **原片不动。** 导入、拍摄、联机接收的文件原样存进 App 的片库；所有调整只是一份参数。
2. **看到的就是冲出来的。** 预览和成片用同一套胶片数据；预览省掉的只有肉眼在屏幕上看不出的微小项，并且写明是哪些。
3. **设备有什么就给什么。** 镜头、手动参数、RAW、录像规格都按设备实际报告的能力显示，没有的不摆出来。

## 3. 四个地方

**监视器、相机、冲印室、观片台。** 冲印室是首页：打开就是片库，点一张底片走进暗房。另外三个从首页底部的一排入口走进去，
用完回到首页；从相机、监视器或观片台里点一张照片进暗房，退出时回到来的地方。监视器连着相机的时候，入口是琥珀色的。

和 2.0 的功能逐项对照见 [功能对照.md](功能对照.md)。

### 3.1 片库

- 按「卷」组织：一次导入、一次拍摄、一场联机各成一卷，卷名默认是日期，可改。
- 一卷展开是印样（接触印相）式的网格：缩略图显示当前冲洗效果，下方是片边式的帧号。
- 导入：系统相册多选、文件管理器（RAW）、其他 App 的「分享到 / 打开方式」。导入即复制进片库，之后不依赖原位置。
- 点一张进入看片：左右滑动换张、双指放大、打星、按住看原片；从这里进暗房。
- 每张底片下面挂着它冲印过的成片（哪天、哪款胶片、多大），可以再次分享或删除。
- 多选后可以：批量套用配方并冲印、移到另一卷、删除。

### 3.2 暗房（调色）

画面在上，下面一条「工序轨」，从左到右就是算法的顺序。点一个工序，下面换成它的控制项。

| 工序 | 它在算法里的位置 | 控制项 |
| --- | --- | --- |
| **原片** | 胶片之前，作用于场景光 | 曝光、色温、色调、高光、阴影、白色、黑色、自然饱和度、饱和度、暗角校正（之后：HSL、降噪、镜头校正） |
| **原片**（续） | 几何 | 画幅：3:2、4:3、5:4、1:1、16:9、65:24，居中裁切，原片不动 |
| **胶片** | 曝光与显影 | 胶片型号、片幅（半格到 4×5，决定颗粒和光晕的尺度）、光晕、颗粒、层间效应 |
| **片边** | 画框外的胶片，和相机后背写在底片上的字 | 片边：片幅、片门形状（含「全开」）、整条/窄边、齿孔、帧号、灰雾、漏光、换机身、印快门与光圈。日期后背：液晶/点阵/仅数据、顺序、位置、角落、字号、亮度、拍摄数据、手动日期 |
| **印相** | 放大机与相纸，或直接扫描底片 | 相纸（或「直接扫描」）、印相曝光、黄/品红滤色、眩光 |
| **整饰** | 成片之后，像修一张扫描件 | 色调曲线（亮度与红绿蓝，可加点）、混色（八个色相各自的色相/饱和度/明度）、色彩分级（阴影/中间调/高光三个色轮，平衡与过渡）、暗角。之后：锐化与局部对比、片边、日期 |
| **构图** | 几何 | 自由裁切、旋转、拉直、翻转（还没有） |

- 滑杆是一把刻度尺：横向拖动，带齿感震动，双击归零，数值用片边字体显示。只有两样东西不是刻度尺，因为它们不是一个数：
  曲线是画出来的（点在曲线上就加一个点，拖出框外就拿掉），色调是在色轮上选的（方向是色相，离中心多远是多浓，双击回到无色）。
- 整饰的顺序是固定的：曲线 → 混色 → 色彩分级 → 暗角。混色在 Oklab 里按色相工作，灰色不会被带偏；
  曲线和色彩分级作用在看到的画面上（sRGB 编码值），和常见修图软件的手感一致。
- 拖动时画面 60 帧实时变化（GPU），不出现「草稿 → 清晰」的跳变。
- 按住画面看原片；撤销/重做；参数自动保存，退出再进来还在。
- 「看底片」（第三阶段）：在胶片工序里可以切到底片本身的样子（橙色片基的负像），这是模型里真实存在的中间结果。
- 片边和日期是曝光在底片上的东西，由引擎画，GPU 预览画不出来。开着它们的时候，画面换成引擎出的一张小样张：
  拖动时先出一张小的，松手后出一张清楚的，上方标着「样张」。缩略图和成片同样带片边。
- 选了片幅，照片按那种片幅的片门居中裁切（6×6 就是方的）。片门选「全开」则没有片门：照片不裁，
  铺满整条胶片，齿孔从画面里穿过去，片边字和条码叠在画面上，成片和照片一样大。
  这时画面旁边没有空的胶片，所以「数据」和日期的「帧间」位置不可用，日期印在两排齿孔之间。
- 配方：顶栏的书签。把「胶片 + 片边 + 日期 + 印相 + 整饰」存成配方，可套用到别的照片、相机和监视器。
  原片工序的校正和画幅属于这张照片，不进配方。在片库里多选之后可以整批套用配方、整批冲印。

### 3.3 相机

- **取景**：实时胶片效果，和暗房是同一份胶片数据、同一段着色器。顶部是相机里装的那卷胶片，点它换卷。
  界面锁定竖屏；照片和视频按手机实际握持的方向保存。
- **镜头**：两种手机都认。新手机把几颗镜头合成一个「逻辑相机」，靠变焦比切换——变焦范围低于 1 的一端就是超广角，
  长焦从它的物理镜头的焦距算出来；老手机和部分厂商把每颗镜头列成单独的相机——按它和主摄的视角比例命名（0.6 / 1 / 3）。
  没有长焦的手机给一个 2（主摄中心裁切）。厂商不对第三方开放的镜头系统不会列出来，这里也就不显示。双指可以连续变焦。
- **设置**：只显示这颗镜头自己报告支持的项——曝光补偿、感光度、快门、对焦、白平衡预设、RAW。
  感光度和快门的刻度尺按档位走（每格 1/3 档），读数是相机上的写法（ISO 125、1/60）；自动时显示相机当前实际用的值。
  感光度和快门动了任何一个，两个一起变成手动（相机的曝光要么自动要么手动），旁边的「自动」一点就回去。
- **照片**：拍下的是原片（JPEG，或设备支持时的 RAW/DNG），按天收进片库里「相机 日期」这一卷，带着当时装的胶片作为冲洗方式，
  之后在暗房可以随便换。JPEG 的明暗是相机和人已经决定好的，原样接收；RAW 和别的 RAW 一样测光，拍摄时拨的曝光补偿记在这张的「曝光」里。
  左下角是刚拍的一张，点开直接进暗房。
- **视频**：胶片效果直接录进画面（视频没有事后的暗房）。画质 1080P / 720P / 480P、帧率按设备支持列出；存进相册 `Movies/Spektramat`。
  有麦克风权限就带声音，没有就无声并标出来。
- **出错时**：系统相机服务崩溃或被占用后，相机自己重新识别镜头并恢复取景，不用退出 App。
- **画幅和构图线**：画幅有 4:3 全幅、3:2、5:4、1:1、16:9、65:24。取景里把会裁掉的部分压暗而不是遮住，原片完整入库，
  画幅记在这张照片的设置里，进暗房还能改。构图线是三分线。
- **机背**（点顶部的胶片名）：胶片、片幅、片边、日期后背、配方；「拍下即冲印」开着时每拍一张就在后台冲一张成片；
  「系统相机」把手机自带的相机叫出来（有的镜头只给它用），拍完照片完整地回到这里。
- **闪光灯**：照片是关 / 自动 / 开，视频是常亮；手机没有闪光灯就不显示。
- 还没有的：取景和视频里没有光晕和片边（片边只在成片上）；4K 视频（逐帧过胶片，要先在真机上量过性能）。

### 3.4 监视器

- USB 连接相机（PTP，现在认 Sony 的「PC 遥控」）。没连的时候是一个接线的地方：相机列表、监看和收片的设置。
- 连上之后就是相机的画面：实时取景（480P / 720P），可以过一遍胶片；下方是相机当前的感光度、光圈、快门。
- 快门键按的是相机的快门；在相机上按也一样。照片传过来时画面底边有一条进度线，收到的原片进片库「联机 日期」一卷，
  带着监视器选的冲洗方式。可以另存一份到 `Download/Spektramat`。
- 录制：把监看画面（带不带胶片都行）录成 MP4，可以把参数烧在画面顶上；存进相册 `Movies/Spektramat`。
- 连接属于 App：连上之后回到冲印室，照片照样在收；没人看的时候不取实时画面。
- 断线不丢片：收完整的原片先改名落盘再登记，中途退出的下次启动补登；片库读不了的文件转存出来，不删除。
  断线后画面留着最后一帧，并标明它是最后一帧。

### 3.5 观片台

- 一张没有边的灯箱。从片库选照片放上来，拖动、双指缩放和旋转，选中后有旋转和缩放手柄；置顶、锁定、拿走。
- 胶片是透明的：开灯时每张照片乘上背光的颜色，两张叠在一起密度相加；关灯只剩屋里的暗光。背光的色温和亮度可调。
- 放大镜是一块真的玻璃：每个像素沿视线穿过一枚平凸透镜（球面折射、出射、边缘的色散和全反射、玻璃上的高光），
  中心的倍率正好是设定值。玻璃用的是 BK7 的真实折射率和色散，曲率比半球平一些，所以边缘弯而不糊。
  Android 13 以下的系统画不了这段着色器，那里是普通的放大圆。
- 吸附：拖动时边和中线对齐到别的照片（出现参考线），否则落在看不见的网格上。「整理」把照片排成行，「全部」看全台。
- 台上放的是片库里的同一张底片：在暗房里改了它，台上跟着变；选中一张可以直接去冲洗。
- 导出：当前窗口，或全部照片。每张照片按它在图里的大小重新读取，不拿屏幕上的小图放大；放大镜按屏幕上的样子存下。

## 4. 冲印指示

冲印在后台进行，不占任何页面：点了「冲印」之后可以接着调、换一张、回片库，多张依次排队。
告诉人「正在冲」的是一个加载指示，不是一场演出——小、快、一直循环到完成。

- **位置**：顶栏下方靠右的一块 56dp 小方片，每个页面都在同一处。不放在屏幕正中，因为正中是看画面的地方；
  它紧挨着「冲印」按钮，点完按钮视线本来就在那里。除了它自己，不拦任何触摸。
- **内容**：这张照片本身，缩成 5×5 的大像素。一道波从左上扫到右下，扫到的像素张开成胶片的三层染料
  （黄、品红、青，和乳剂里的上下顺序一致），再合上变成冲洗后的颜色；下一道波把它带回原片，循环没有接缝。
  一趟 0.85 秒。
- **进度**：方片外圈的琥珀色线跟着引擎真实的阶段走（读取、曝光、显影、印相、扫描、保存）。
- **完成**：大像素分几步变细，直到就是成片，方片略微变大并震动一下。点开是带相纸白边的成片，可以分享；
  不点，5 秒后自己收起（成片已经在相册里）。
- **点开进行中的方片**：看到是哪一张、到了哪一步，可以停止；停止不留下任何文件。
- **失败**：外圈变红并留在原处，点开说明原因。

## 5. 视觉与手感

- **中性的暗环境。** 照片周围是不带色偏的黑和灰（判断颜色需要中性的环境），界面本身不抢画面。
- **一种强调色：安全灯琥珀 `#F2A93B`。** 只用在「当前值、当前工序、进度」。红色 `#E5484D` 只给录制和删除。
- **片边字体。** 所有数值、帧号、胶片名用窄体无衬线（TeX Gyre Heros Condensed），和胶片片边上印的字是一路；中文用系统字体。
- **刻度尺** 是唯一的调节控件，全 App 一致。
- **动效只回应操作**：进暗房时缩略图长成大图；换工序时控制区横移。
- **字符矩阵**是 App 在等待、空着、或者东西还显示不出来时的样子：一格格等宽字符，疏密跟着一片亮度走。
  启动时 SPEKTRAMAT 从字符里立起来；片库和观片台空着时是缓慢流动的字符；监视器没接相机时是 USB；
  点开冲印指示，这张照片从字符里一行行显出来，显到哪一行就是引擎真的做到了哪一步，每个字符是照片在那一格的颜色。
  标题、胶片名、相机型号出现和变化时，字符先乱跳几下再落定（不到半秒，只在内容变了的时候）。
  系统里关掉动画时，这些都是静止的。

色板：幕布 `#0C0C0C`、机身 `#161616`、刻线 `#2B2B2B`、次要文字 `#8A8A8A`、主文字 `#EDEDED`、琥珀 `#F2A93B`、相纸白 `#F1EEE6`（只用于成片的白边）。

## 6. 技术结构

```
Spektramat/
  engine/   C++：spektrafilm 胶片引擎、RAW 解码（内置 + LibRaw）、调色算法；JNI；胶片数据 engine.bin
  app/      Kotlin + Jetpack Compose：界面、片库（数据库）、GPU 渲染管线、相机、联机
  docs/     本文件
```

- **胶片引擎**沿用 2.0 里那份逐阶段对照 spektrafilm 移植的 C++（它本身就是算法，不是界面），不重写。
- **实时预览走 GPU**：调色（片元着色器）→ 光谱曝光表 → 特性曲线 + 层间效应 → 底片密度 → 印相/扫描表 → 屏幕。
  这些表由 CPU 引擎按当前胶片/相纸/滤色现算出来，所以 GPU 画面和 CPU 成片出自同一份数据。
- **成片走 CPU 引擎**：全尺寸、全部空间效应（光晕、颗粒、层间扩散、眩光、锐化）。
- **调色算法只写一份**：同一个文件既编译成着色器，也编译成 C++，预览和成片不会各算各的。
  原片工序的校正和整饰工序都在这个文件里；成片时，整饰接在引擎最后一步的线性画面后面，由同一段代码编码成 8 位。
- **片库用数据库**（事务、崩溃不丢），原片与缩略图在 App 私有目录，成片写进系统相册 `Pictures/Spektramat`。

## 7. 分期

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 一 | 主线：片库（导入）→ 暗房（原片/胶片/印相，GPU 实时）→ 后台冲印 → 成片 | 已通，模拟器上验证过 |
| 二 | 相机：胶片取景、镜头识别、手动参数、RAW、视频 | 已通；模拟器上验证过，一台真机上取景、镜头、RAW 通过（见下），JPEG 和录像在真机上还没测 |
| 三 | 调色补全：曲线、HSL、色彩分级、片边、日期、画幅、配方、批量 | 整饰、片边、日期后背、片幅、画幅、直接扫描、配方、多选套用配方和冲印已通（模拟器）；自由裁切、局部对比、锐化开关未做 |
| 四 | 监视器：USB 接收、实时取景、遥控快门、监看录制 | 代码已通，用调试版的演示相机在模拟器上走过全流程；**没有接过真相机** |
| 四（续） | 观片台：灯箱、摆放、放大镜、背光、导出 | 已通（模拟器；玻璃放大镜在 Android 16 模拟器上看过） |
| 五 | 打磨：真机适配、性能、16 位与广色域输出、平板与折叠屏 | 未开始 |

真机相关的部分（各家手机的镜头与手动能力、各家相机的联机协议）只能在真机上验收；模拟器上能验证的会写明是在模拟器上验证的。

相机在模拟器上验证到哪一步：

| 项目 | Android 12 模拟器 | Android 16 模拟器 |
| --- | --- | --- |
| 胶片取景、换卷、镜头档位、曝光补偿、白平衡 | 通过 | 通过 |
| 拍 JPEG 进片库、从相机进暗房 | 这个镜像的相机驱动一压 JPEG 就崩溃（任何 App 都一样），无法验证 | 通过 |
| 手动感光度 / 快门 | 它的相机不支持，界面不显示这两项 | 前置相机支持，拨动后画面明暗跟着变 |
| RAW | 不支持，界面不显示 | 取景和拍摄通过；写 DNG 时系统报缺少元数据（模拟相机不给），文件没写成 |
| 录像（胶片效果在画面里） | 通过，720×1280，文件可播放 | 未单独再测 |
| 相机服务崩溃后自动恢复 | 通过 | — |

模拟器用 CPU 模拟 GPU，取景和录像每秒只有几帧；真机上的帧率、多镜头手机的档位、RAW 文件，都要在真机上看。

第一台真机（2026-11-11，vivo V2454DA，骁龙 SM8750 / Adreno 830，Android 17）：

| 项目 | 结果 |
| --- | --- |
| 启动、胶片引擎、GPU 管线 | 通过，日志里没有警告和错误 |
| 胶片取景 | 每秒 30 帧（相机给的就是 30 帧），每帧绘制约 1.2 毫秒 |
| 镜头 | 认出 0.6 / 1 / 2：系统公开的后置相机是一个逻辑相机，含超广角和主摄，变焦 0.65–10。这台手机的 85mm 长焦系统没有对第三方 App 公开，所以没有；2 是主摄裁切 |
| 手动项 | 曝光补偿、感光度、快门、对焦、白平衡、RAW 全部显示 |
| RAW | 通过：拍下 25 MB 的 DNG → 进片库 → 暗房 → 原尺寸成片 3072×4096，出片约 8 秒。同一个 DNG 用 LibRaw 解出来和 App 的原片颜色一致（桌面灰块红绿比 0.995 对 1.028，蓝绿比 0.900 对 0.895） |
| 拍 JPEG、录像、前置相机 | 还没有测 |

取景和镜头是从 App 写进日志的诊断信息读出来的：打开相机时每个相机报告的焦距、传感器、变焦范围和能力各记一行（`latent-camera: camera …`），
调试包每两秒记一次取景帧率。换一台手机镜头不对时，先看这几行。

# 视频专用完整 LUT：实现与验证

参考版本：spektrafilm `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`。

## 实现

视频不再使用旧 `FilmTables` 的 tc/曲线/enlarger/scanner 表组合。新的 `VideoLut` 直接向完整原生引擎提交 65³ 个采样点，读取最后的 `rgb_out_linear`：包含输入 sRGB 解码、场景 grade/手动曝光、光谱胶片曝光、胶片显影与逐像素 DIR、精确光谱印相、相纸显影、精确光谱扫描和输出 gamut compression。成片 finishing 和输出 sRGB CCTF 在视频 shader 的 LUT 之后执行。

采样域为相机的 SDR 编码 sRGB `[0,1]`，sRGB CCTF 作为 shaper。曝光/WB/grade 在解码之后、胶片曝光之前烘焙，因此增曝光不会先把线性场景高光裁到 LUT 边界。当前不支持 HDR/Log 相机输入。

`pointwise-exact-v1` 视频 preset 明确关闭图像全局、空间与随机处理：auto exposure、highlight boost、camera/enlarger diffusion、lens blur、halation/scatter、DIR diffusion、grain、glare、unsharp 和 scanner black/white correction。保留配方手动曝光与印相曝光；manual EV 在 grade 中应用一次，print compensation 关闭。此实现没有加入这些效果的独立视频 GPU pass；界面与开始录制提示说明关闭状态。

LUT 只在相机处于视频模式时异步构建，GL 线程原子替换。只有 `CameraEffect.VIDEO_CAPTURE` output 可以使用 LUT，照片 capture 和 viewfinder 不进入该 shader。录制前 LUT 必须与当前 Look 一致，未就绪则给出提示；录制与编码结束前锁定配方修改。

metadata 包含参考 commit、资产 key、输入/输出空间、shaper、分辨率、film/paper、全部 render/grade/model 参数和 LUT 内容 SHA-256。metadata 写入开发日志；当前没有持久化磁盘 LUT 缓存或写入 MP4 容器。

Sony USB 监看也遵守同一规则：非录制时执行完整照片引擎，录制时由相同 baker 生成 cube 并用 CPU trilinear 采样，再执行 finishing。录制期间锁定 look、胶片开关和分辨率，结束后释放 cube；收到的原始照片仍通过完整照片管线处理。

手机相机在照片模式和视频待机时使用独立的 GPU 取景 LUT；从开始录制到编码完成期间，取景使用同一视频 preset 的 GPU LUT。拍下的照片继续完整算法。取景实现及最新验证见 [GPU 实时预览记录](相机GPU实时预览-2026-11-12.zh-CN.md)。

## 验证

命令：`pwsh -NoProfile -File tools/host/run_video.ps1 -OutputDirectory build/video-lut-delivery`。

每场景用固定种子的 1024 个随机输入，比较 CPU 同序 trilinear LUT 采样与独立 exact engine 渲染；输入均不依赖 LUT lattice。误差在最终 sRGB 编码值中测量。

| 场景 | 最大误差（8-bit code） | RMS（8-bit code） |
|---|---:|---:|
| Portra 400 默认 | 0.6662 | 0.0467 |
| Portra 400，曝光 +1.25 EV、印相增益 1.4、Y +12/M -8 | 0.5037 | 0.0515 |
| Ektachrome 100 正片直扫 | 0.5212 | 0.0427 |
| HP5 Plus 400 + Multigrade IV 黑白印相 | 0.2037 | 0.0308 |

`VIDEO_LUT_FAILURES 0`。验收阈值为 max ≤ 2 个 code、RMS ≤ 0.25 个 code。

API 31 模拟器的 `VideoLutGpuTest` 已编译生产 external-camera shader，再通过相同 shader 的 2D 输入适配、生产 `VideoLutGpu`/finishing 渲染 16×16 固定随机 RGB8 输入并读取 FBO。相对 native CPU sampler 的最大差异为 **1 code**，RMS 为 **0.03609 code**；门槛为 max ≤1、RMS ≤0.25。没有关闭生产默认 dither。此测试验证 shader、轴顺序、浮点纹理上传和采样，不包含真实相机 OES 帧与编码器。

这些结果验证当前 C++ exact engine 与其完整 LUT 的近似误差，不能替代 C++ 对 Python spektrafilm 的 parity，也不能证明所有 25 款胶片/9 款相纸组合的 LUT 误差均满足阈值。真实录制帧、方向、稳定性与性能仍须真机验证。

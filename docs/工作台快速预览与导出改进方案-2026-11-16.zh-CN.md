# 工作台快速预览、原图导出与白位挡位修改方案

日期：2026-11-16。代码阅读基线：`91c62f9`。本文保留实施前的需求及方案；实施结果与已完成的验证见 [实施记录](工作台快速预览实施记录-2026-11-16.zh-CN.md)。

## 1. 需求定义

工作台以调整响应速度为优先：胶片/相纸候选图、切换胶片和拖动参数优先使用低分辨率代理与 GPU LUT。照片导出始终重新读取原始文件，在原始分辨率上执行完整照片算法，最后根据导出选择缩放、编码和保存。

- 原始文件与编辑配方分开保存；编辑和代理生成都不改写原始文件。
- 预览的降分辨率、显示量化及 LUT 近似不得进入最终照片导出链路。
- 导入照片继续禁止场景自动曝光与印相曝光补偿；手动 EV 只应用一次。
- 代理是从原图产生的工作副本，不是把一个渲染结果继续累加修改。每次显示都由同一份未套胶片的代理和当前配方生成。
- 白位提供“原始白位”和“完整扩展”两挡，默认使用原始白位。
- 导出错误不能显示成功；保存位置必须准确；相册拒绝时保留可分享的文件。

## 2. 当前实现与性能瓶颈

| 位置 | 当前行为 | 结论 |
| --- | --- | --- |
| `DarkroomState.load()` | 原图解码成最长边 2048 的线性 float32 图像，内存中另保留最长边 1100 的样张源 | 已有内存代理的概念 |
| `DarkroomState.makeProof()` | 拖动时最长边 560，停手后 1100，仍执行完整算法；“调节”页单独执行原图调节 | 代理减少像素数，但未解决完整算法重复执行的成本 |
| `Stocks.StockSample()` | 每个未命中的候选图都重新解码原图到最长边 180，再完整处理；任务串行；缓存为 JPEG | 胶片列表存在重复解码与逐候选完整渲染 |
| `Library.proxy()` | 按照片修订号生成已套效果的 JPEG，默认最长边 1600，用于观片台 | 已有磁盘代理，但它是展示用成片，不适合作为继续调整的输入 |
| `Library.saveLook()` | 在目录互斥锁内重新解码并完整处理 640 缩略图，随后才更新数据库 | 保存配方、缩略图计算与目录操作耦合 |
| `Printer.print()` | `Decoder.decode(..., 0, ...)` 读取原生尺寸，经 `developFloat()` 完整处理，再缩放与编码 | 工作台照片导出已经使用原图，而非屏幕代理 |

工作台的 GPU `FilmPreview` 当前主要负责原图对比显示，不执行胶片 LUT。相机已有 `PreviewLut` 和 GPU 上传组件，但其原生参数转换继承视频约束，会关闭白位校正并固定 sRGB 输出，不能直接复用为工作台的完整语义。

## 3. 代理资源设计

建议新增统一的工作台代理服务，集中负责解码、共享、缓存与资源释放。

1. 一份未套胶片、未量化为显示 Bitmap 的线性 float32 源代理，默认最长边 1280；内存紧张设备降至 960。
2. 候选胶片/相纸图从同一份源代理再缩至最长边 128，不逐候选重新打开原图。
3. 主画面交互阶段以最长边约 720 的离屏目标渲染，停手后提升至 1280；实际显示比例和画框手势保持一致。
4. 代理缓存键使用原始文件身份/指纹、解码器版本、方向、镜头校正和裁切形状；曝光、胶片及相纸变化不使源代理失效。
5. 磁盘保存未套效果的浮点代理，内存提供受预算控制的 LRU。缓存具有尺寸、色彩空间、样本类型与版本信息，采用临时文件和原子发布。
6. 已渲染的 JPEG 缩略图继续作为展示缓存使用，但不能进入调节源或照片导出。
7. 快速切图、横竖屏、退出工作台时安全取消并释放图像/纹理；过期任务不得发布结果。

首次遇到 RAW 仍可能需要完整解码才能生成精确代理。可先显示已有缩略图，浮点代理就绪后替换；不把相机内嵌 JPEG 当作原始 RAW 导出源。

## 4. LUT 预览

### 4.1 生成规则与成本

新增独立工作台 LUT 参数转换与缓存服务，复用现有 GPU 上传及采样设施，保留照片专用语义：白位挡位、胶片/相纸、负片/反转片扫描、层间作用、印相滤色及相关光谱配置。

LUT 必须由当前完整引擎采样生成，覆盖其可逐像素表达的胶片曝光、显影、印相与扫描转换，不使用外部风格 LUT，也不恢复旧的简化照片管线。

- 候选列表建议使用 33³ LUT；主画面建议使用 65³ LUT。它们是起始配置，最终尺寸按观感误差和设备性能决定。
- 现有相机 LUT 默认 97³；直接为每个候选胶片临时生成 97³ 会抵消提速收益。33³ 的采样点约为其 1/25。
- 打包或开发时预生成常用默认组合；运行时优先加载缓存。自定义配方首次使用的 LUT 异步生成并持久化，缓存未命中不能阻塞界面。
- 缓存键覆盖所有实际参与烘焙的参数、算法/素材版本、采样域、LUT 尺寸及输出配置。只影响源调节、整饰或几何的参数不重复烘焙。
- 当前选中胶片和可见项优先，最多预取相邻少数项；不预计算全部胶片、相纸和参数的笛卡尔积。

### 4.2 交互行为

1. 打开胶片列表：已有小图立即显示，当前及可见候选图优先刷新；候选图不再调用完整照片渲染。
2. 选择胶片：使用就绪 LUT 立即刷新主画面；首次未命中时保留可见图像并显示加载状态，完成后只发布最新选择。
3. 曝光、白平衡和普通调节通过 GPU 参数更新；完整引擎中的手动曝光与 GPU 曝光分工明确，禁止应用两次 EV。
4. “调节”页继续显示经过源调节的原图，绕过胶片转换；调节页与胶片页共享原始代理及编辑配方。
5. 影响胶片转换的自定义参数采用合并请求、异步更新 LUT；旧任务取消，避免拖动产生长队列。未完成的新参数不能被误标为已显示。
6. 放大、平移、原图长按和分割线对比只更新显示几何，不触发解码或完整算法。
7. 波形/直方图等读取当前低分辨率预览并节流，不为其额外执行完整引擎；若显示的是原图直方图，应明确区分。

### 4.3 空间效果与准确校样

静态 LUT 无法精确表达颗粒、光晕、空间扩散、眩光、锐化和片边/日期的曝光过程。快速预览允许这些效果采用轻量近似或延后计算，但不能宣称 LUT 等于完整成片。

建议交互中始终使用 GPU；停手约 600 毫秒、列表关闭且没有导出抢占资源时，低优先生成一次最长边约 960 的完整校样，以观察空间效果。需要时可提供“精确预览”入口。快速调整立即打断校样，不因每次点击重启高成本计算；不自动升级到原生分辨率校样。

LUT 的输入直接取浮点源代理，不先转换成 8 位 sRGB。采用适合高动态范围的采样域及 shaper；检查负值与超域输入，不能把相机 SDR 的 `[0,1]` 边界无声套到 RAW 代理。屏幕无法显示的范围不代表原始数据被删除；导出与 LUT 采样域完全独立。

## 5. 白位两挡

“21x”理解为白色输入经某些胶片/相纸和扫描配置后，8 位显示值约为 210 多。它不是固定倍率，也不是所有材料共有的固定上限。原算法根据胶片、相纸密度与扫描条件得到纸白，不能硬编码为 215、219 或其他猜测值。

| 挡位 | 定义 |
| --- | --- |
| 原始白位（默认） | 不进行额外白位扩展，保留完整引擎原始纸白/片白及影调；遵守当前照片关闭自动曝光的产品策略 |
| 完整扩展 | 根据材料的参考黑白计算映射，使参考白亮度对应输出白点 1.0；保留参考黑及色彩关系，不按当前照片最大值做自动归一化 |

具体约束：

- 使用固定的材料参考，而非照片直方图；纯白背景或画面内容变化不得触发自动曝光。
- 沿用参考算法相应中灰标定逻辑；白位扩展对影调的影响需作为预览/导出的同一个参数处理。
- 完整扩展目标为 1.0，不能只是保留现有默认 `scannerWhiteLevel = 0.98`。
- 白位以亮度定义，不分别拉伸 R/G/B，不额外执行自动白平衡；材料本身的色偏可以保留，因此不承诺带色纸白的三个通道都等于 255。
- 当前 `ColorReference.apply()` 的 `[0,1]` 硬限制需要处理：扩展时保留有限的负值和大于 1 的浮点结果，检查近零亮度处的数值稳定性。此处是相对参考实现的明确产品扩展。
- TIFF 保存浮点值；仅屏幕显示及用户主动选择的 JPEG 编码阶段转换至显示/文件支持的范围。
- 不经过相纸的负片直扫仍不提供这个挡位；相纸印相和反转片扫描提供。
- 新配方显式持久化挡位，进入 LUT 缓存键。旧配方关闭白位时迁移为原始挡；旧配方开启及自定义白位的兼容规则需明确记录，避免无提示地改变已有作品。

## 6. 照片导出可靠性修改

### 6.1 保持现有正确链路

原始文件 → 原生尺寸解码 → 场景手动调节 → 完整胶片/相纸/扫描与空间效果 → 浮点整饰 → 按需缩放 → 编码 → 保存。

保留 `developFloat()` 对 RAW 内嵌预览的导出拒绝。运算保持 float32；原始文件和其源精度信息保留，不把“float32 运算”描述为文件原始位深完全不变。默认浮点 TIFF 携带 ICC，JPEG 是用户主动选择的 8 位分享格式。

### 6.2 需补齐的保存边界

1. **发布结果检查**：`saveGallery()` 当前没有检查 `resolver.update(... IS_PENDING=0 ...)` 的返回行数。返回 0 时不能报“已存入相册”；转入明确的失败或兜底状态。
2. **避免重复编码**：建议完整结果先编码为应用管理的临时文件，再向相册复制。同一文件也作为相册拒绝时的保底，不必重新编码整张浮点 TIFF。
3. **原子文件保存**：应用目录使用临时文件、成功关闭流后原子改名；编码、复制、磁盘满或发布失败均清理半文件，保留有效成片。
4. **唯一命名**：当前名称使用秒时间戳模 100000，同名照片在同秒导出可能重名；应用目录的 `outputStream()` 会覆盖旧文件。改用毫秒和唯一 ID 或独占创建，保证重复导出不覆盖。
5. **取消边界**：当前只在解码/渲染前后检查 `shouldStop`，保存时缺少取消检查。编码、复制与发布前补检查，并定义发布后的取消不删除已成功成片，避免界面宣称取消但文件状态不明。
6. **成功状态分离**：成片已保存后，目录登记或显示缩略图失败不得误报为“导出丢失”。先确定文件保存结果，缩略图异步生成；记录失败能恢复/重试。
7. **错误分类**：相册权限错误才走相册兜底；数据编码失败、资源不足和取消应明确传播，不把全部异常描述成“相册拒绝”。清理异常不能覆盖原始错误。
8. **后台任务资源**：完整导出串行，工作台交互优先，低优先校样和旧缩略图让出资源；大图内存失败给出可理解错误，不静默改用代理导出。

另外发现观片台拼版导出是另一条独立链路：`TableScreen.export()` 使用已处理的 JPEG 代理进行拼版，并有独立的相册保存逻辑。它不等于工作台照片的原图导出。本轮应复用可靠保存组件；如将“所有照片导出均用原图”的约束覆盖到拼版内部照片，也应改为原图完整处理后再按版面缩小合成，不能复用展示代理作为母版。拼版最终 JPEG 的位深限制应继续由其文件类型明确表达。

## 8. 验收标准

- 缓存命中的胶片候选图不执行原图解码与完整照片引擎；同一照片所有候选共享源代理。
- GPU 普通调节不重烘焙 LUT、不重解码原图。连续拖动只显示最新参数，无排队回放、旧图覆盖或重复曝光。
- 在同一台 ADB 真机上比较冷启动、热缓存、胶片切换、调节延迟、峰值内存及持续操作；热缓存切片约 100 毫秒、调节达到 30 fps 作为初始目标，最终报告实测值，不提前承诺所有设备达到。
- 验证彩色负片、黑白、反转片与相纸组合；白棚、灰阶和高动态场景中，白位挡位不依赖照片内容自动改变。
- 同参数 LUT 与完整校样比较色彩/影调误差；空间效果另行观察，不把完整算法与 LUT 近似宣称逐像素一致。
- PNG8/16、JPEG、TIFF16/float32 和支持的 Sony RAW 分别导出；检查尺寸、方向、裁切、片边、日期、ICC、文件能否重读及原始文件哈希不变。
- float TIFF 特定样本验证负值、超过 1 和相邻精细差值保留；JPEG 验证显式色彩转换后的显示结果。
- 覆盖正常相册、拒绝写入、发布返回 0、应用目录兜底、磁盘满、重复导出和各阶段取消；只有文件完整保存并有真实位置时才能显示成功。
- 删除代理或强制生成另一分辨率代理，不应改变同参数、同随机种子的原图导出结果；这是预览与导出隔离的直接验收项。

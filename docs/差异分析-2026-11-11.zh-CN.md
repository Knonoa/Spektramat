# Spektramat 与 spektrafilm / SpektraLab 差异分析

> 本文是对 `Knonoa/Spektramat` 安卓应用与上游 `spektrafilm`、`SpektraLab` 的代码和功能差异审计。结论基于本地拉取的远端最新提交、源码阅读和主机端数值检验，不把“计划功能”当成已实现功能。

## 1. 对比对象与方法

| 对象 | 本次对比版本 | 定位 |
| --- | --- | --- |
| Spektramat | `e7baa584bf631d64e23e7acc639f81cacbc673ed`（与 `origin/main` 一致） | Android 产品、C++/OpenGL ES 胶片引擎、CameraX、Sony PTP 监视器、片库和灯箱 |
| spektrafilm | `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`（远端最新） | Python 光谱参考实现、桌面 Qt/Napari GUI、实验和 LUT 生成工具 |
| SpektraLab | `1952c63537ec576d24422f1065b12495631346a5`（`spektralab-v2.3.2`） | macOS 产品、完整工作空间/目录、广色域和高级输出 |

检查步骤：

1. 更新三个仓库并记录上述提交；对照引擎、共享着色器、Kotlin/Compose UI、SpektraLab 的 Swift 模型和架构文档。
2. 运行 `Spektramat/tools/host/run.ps1`，覆盖 25 款胶片、GPU/CPU 表路径、颗粒、整饰、片边和中性灰检查；结果为 `FAST_VS_ENGINE_FAILURES 0`。
3. 用 parity 工具将最新 spektrafilm Python runtime 与 Spektramat C++ engine 对比：160×120 图像、−12…+6 EV、全色相/饱和度 sweep，并关闭空间和随机效果；再单独检查 EV、滤镜、印相曝光和极端 DIR 参数。

## 2. 结论摘要

Spektramat 沿用了 spektrafilm 的四段主流程：**场景曝光 → 胶片显影 → 印相/直接扫描 → 扫描输出**。在常规参数范围内，它的 C++ 引擎与 spektrafilm 参考实现非常接近；四种代表性胶片/相纸组合与典型曝光/滤镜/印相变化的最大误差为 1 个 8-bit code。Spektramat 自身的 25 款胶片 fast/full 主机检查也通过了各自阈值。

两者的主要差别来自移动端的性能和产品约束：Spektramat 将光谱积分预烘焙为资产，成片使用 41³ 三线性 LUT；输入固定为 scene-linear sRGB、输出为 RGBA8 sRGB；自动曝光在导入时测一次；预览为近似路径。spektrafilm/SpektraLab 则保留 81 波长积分、更多色彩空间、可选曝光意图和完整空间效果。

当前最明确的数值边界问题是 DIR 层间耦合：Spektramat UI 允许 0…200%，而 SpektraLab 已将安全范围限制为 0…1.5（150%），因为约 1.736 以上耦合反演轴失去单调性。把 `dir_couplers_amount` 设为 2 时，输出最大差达到 87 个 8-bit code，p99 为 52，约 12.95% 通道样本差异超过 2 code。

功能上，Spektramat 把参考模型包装成了移动端暗房：手机相机和录像、Sony USB 监视器、卷式片库、后台批量冲印、片边/日期后背和灯箱观片台是其产品增量。SpektraLab 的目录、变体、广色域/HDR、数字中间片、半格拼接和专业导出仍未移植。

## 3. 算法差异

### 3.1 流程与输入输出

| 环节 | spektrafilm / SpektraLab | Spektramat | 影响 |
| --- | --- | --- | --- |
| RGB→胶片曝光 | Hanatos 2025 光谱上采样；Spektrafilm 也保留 Mallett 2019 方案 | 只启用 Hanatos 2025；每个胶片预烘焙 192² 的 tc LUT，资产使用 fp16 | 普通输入已验证接近；无法在 App 中切换上采样算法 |
| 负片显影 | 特性曲线、DIR 矩阵、完整颗粒模型；空间扩散可参与 | 全尺寸 C++ 保留曲线、DIR 和颗粒模型 | 成片模型相近；参数暴露范围不同 |
| 印相/扫描 | 可按 81 个波长做光谱积分，也可选择 LUT；更完整的纸张/扫描参数 | 固定使用 41³ 印相和扫描 LUT，三线性插值（`spektra_engine.cpp`） | 速度和包体更适合手机，极端色彩/边界会有近似误差 |
| 色彩工作空间 | 可配置输入/输出色彩空间；SpektraLab 内部为 ProPhoto RGB，输出可 sRGB、Display P3、Adobe RGB、ProPhoto RGB | scene-linear sRGB 输入，RGBA8 sRGB 输出 | 广色域 RAW 和 16 位输出能力较弱 |
| 输出变换 | 可选 CCTF、HDR/EDR、输出色域压缩 | CAM16 色域压缩后固定锐化并编码 sRGB | 无 HDR/EDR 和专业输出空间选择 |

关键实现：[spektra_engine.hpp](../engine/src/main/cpp/spektra_engine.hpp)、[spektra_engine.cpp](../engine/src/main/cpp/spektra_engine.cpp)、[latent.glsl](../engine/src/main/shared/shaders/latent.glsl)。

### 3.2 自动曝光

Spektrafilm/SpektraLab 把自动曝光作为每次渲染可配置的相机参数，并支持不同测光意图。Spektramat 在导入时对缩小图做一次中心加权测光，之后关闭 JNI 成片阶段的引擎自动曝光，由用户曝光滑杆在测光值上加减。因此同一张照片更换配方时不会再次改变基础测光，但也没有 SpektraLab 的 AE 方法选择和逐次重测开关。

### 3.3 光晕、散射和空间效果

Spektrafilm 暴露散射强度/尺度、反射或光晕强度/尺度等独立参数；SpektraLab 还把空间参数和胶片幅面关联。Spektramat 的全尺寸冲印保留散射、光晕和幅面尺度，`Look` UI 只有一个总量滑杆；暗房预览在最长边 512 的缓冲上用单高斯近似（[FilmPreview.kt](../app/src/main/java/com/spektra/latent/gl/FilmPreview.kt)）。相机/录像实时预览为保持帧率完全不做光晕和邻域效果（[Programs.kt](../app/src/main/java/com/spektra/latent/gl/Programs.kt)）。

### 3.4 DIR 层间效应

Spektramat 的 CPU 引擎实现了同层/层间耦合矩阵和扩散，GPU 预览在当前像素上执行矩阵修正；它没有在预览中执行完整的邻域扩散。SpektraLab 将 UI 耦合范围限制为 0…1.5：

- [FilmParams.swift](../../upstream/SpektraLab/app/SpektraLab/Sources/Model/FilmParams.swift) 的 `couplersRange = 0.0...1.5`，注释说明约 1.736 后反演轴不再单调。
- Spektramat [Look.kt](../app/src/main/java/com/spektra/latent/model/Look.kt) 将 `interLayer` 暴露为 0…200%。

这是需要优先修正的算法边界：建议先把 UI 和序列化校验上限设为 150%，对旧配方加载时进行钳制并给出提示。

### 3.5 颗粒

Spektrafilm 的颗粒是按乳剂层建模的随机 Poisson/binomial 过程，可包含染料云、子层和微结构。Spektramat 全尺寸路径保留多层颗粒模型；GPU 预览读取预计算均值/方差表，加高斯噪声，见 [latent.glsl](../engine/src/main/shared/shaders/latent.glsl) 的 `film_grain`。因此预览能保持稳定且快速，但不是逐粒子随机过程。SpektraLab 还为黑白胶片提供单层颗粒和 stock grain calibration，Spektramat 尚未提供同等级的校准选项。

### 3.6 放大机、扫描和 RAW

Spektrafilm 支持预闪、diffusion filter、滤镜偏移、镜头模糊、黑白点和可调扫描锐化；SpektraLab Mac 保留预闪和更多扫描/产品控制，但它的原生引擎明确拒绝 diffusion filter。Spektramat UI 主要提供印相曝光、Y/M 滤镜、眩光和固定锐化；预闪、移除防光晕层、完整扫描参数和通道混合器没有对应控制。Spektramat 使用 LibRaw/自有 DNG 解码并转 linear sRGB，没有 SpektraLab 的 ProPhoto 工作流，也没有 spektrafilm 工具链可选的 Lensfun 镜头校正。

## 4. GPU 预览与全尺寸成片

| 功能 | 暗房预览 | 全尺寸冲印 | 相机/录像预览 |
| --- | --- | --- | --- |
| 胶片曲线、印相 LUT、整饰 | 有 | 有 | 有（同一胶片表和整饰基础） |
| 光晕 | 512 长边缓冲、单高斯 | 完整 C++ 模型 | 无 |
| DIR 扩散 | 当前像素矩阵近似 | 有扩散/邻域模型 | 无邻域效果 |
| 颗粒 | 均值/方差表 + 高斯噪声 | 完整随机模型 | 低成本表 + 噪声 |
| 片边、日期后背 | 缩略图/样张可见 | 有 | 取景中不叠加片边和日期 |

因此 UI 上看到的实时画面与最终全尺寸文件不应被理解为逐像素等价，尤其是光晕、DIR 扩散和颗粒。建议在 UI 中明确“预览近似、全尺寸冲印生效”的标记。

## 5. 数值 parity 结果

关闭空间和随机效果，使用 160×120 输入并覆盖 −12…+6 EV、全色相/饱和度：

| 场景 | 结果 |
| --- | --- |
| Portra 400 / Endura | 最大差 1 个 8-bit code |
| Ektachrome 100 直接扫描 | 最大差 1 |
| HP5 / Multigrade | 最大差 1 |
| Vision3 500T / 2383 | 最大差 1 |
| Portra + EV、滤镜、印相曝光变化 | 最大差 1 |
| `dir_couplers_amount = 2` | 最大差 87；p99 52；约 12.95% 通道样本差异 > 2 |

Spektramat 自带主机检查还验证了 25 款胶片、GPU/CPU 表路径、颗粒、整饰、片边和无滤色数据时中性灰，命令为：

```powershell
pwsh -NoProfile -File Spektramat/tools/host/run.ps1
```

通过标准是最后一行 `FAST_VS_ENGINE_FAILURES 0`。这些结果证明常规范围内的移植是可靠的，但不能证明高耦合、极端广色域、HDR 或随机颗粒逐样本一致。

## 7. 风险与优先级建议

### P0：限制 DIR 耦合范围

将 `Look.kt` 的 `interLayer` 控件和配方反序列化上限从 200% 调整到 150%（或更保守的 1.5），对旧配方钳制并记录迁移。保留引擎对非法值的保护，避免用户在 UI 中触发非单调反演。

### P1：明确预览与成片差异

在胶片/光晕/颗粒/DIR 控件旁标明实时预览采用近似，完整空间效果在全尺寸冲印中生效。相机和录像预览还应说明不包含光晕和邻域扩散。

### P1：补齐颗粒校准

为黑白胶片加入 SpektraLab 的单层颗粒和 stock grain calibration，至少将“层数/校准来源”写入资产元数据，避免仅凭均值/方差表调参。

### P1：把资产和 parity 工具纳入可复现构建

源码注释引用 `tools/bake_assets.py` 和 `tools/parity`，但 `Spektramat/tools` 当前只有 `tools/host/run.ps1` 与 `fast_vs_engine.cpp`；生成器位于 workspace 外层 `F:\LocalProject\SpektraLab\tools`。建议将生成脚本、profile 提交号、输入哈希和生成命令纳入仓库或发布包，并在 CI 中对最新 spektrafilm 做自动 parity。

### P2：扩展移动端输出和工作空间

按用户价值排序考虑：16 位 TIFF、8 位 HEIF/PNG、Display P3/Adobe RGB/ProPhoto RGB、自由裁切/透视校正、预闪和扫描控制、通道混合器、可恢复的批处理队列、评级/色标/变体。HDR/EDR、数字中间片和半格双图属于更大的工作空间功能，应单独设计数据模型。

## 9. 范围和限制

本报告比较的是仓库当前代码和已运行的主机检验。Sony 真相机连接、手机闪光灯、系统相机回传、拍下即冲印和部分录像路径仍需要真机验证；因此功能矩阵中的这些项目按“代码已有、设备未验”理解。报告没有把未来分支或未合并的 SpektraLab 设计文档计入已实现能力。

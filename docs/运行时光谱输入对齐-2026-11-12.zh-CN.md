# 运行时光谱输入对齐与验证

基准为 spektrafilm `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`，产品 profile 来自 SpektraLab `1952c63537ec576d24422f1065b12495631346a5`。

## 已接入的运算

`RenderParams.spectral_input` 与 Android `PhotoModel` 共同传递以下参数：Hanatos 2025 / Mallett 2019、UV/IR 的幅度/中心/宽度、Hanatos adaptation window/surface、spectral Gaussian blur、input gamut 开关、xy / Oklch 算法和 knee。

UV/IR 先改变 sensitivity，再按 reference illuminant 的每通道响应归一化。Hanatos 对该 sensitivity 应用保白的 adaptation window，再积分原始 irradiance spectra，之后应用 surface correction 并把 gamut remap 双线性重采样到 TC 表。照片禁止的是印相/扫描 3D LUT；这里的光谱上采样 TC 表是 spektrafilm 原算法本身使用的数据结构。

Mallett 由同一 sensitivity、illuminant、原始 basis 和绿色 midgray normalization 构建矩阵。它保留 `colour.RGB_to_RGB(sRGB, sRGB)` 对已舍入的 RGB/XYZ 矩阵进行往返转换的行为，避免把它错误简化成单位矩阵。

默认参数复用离线生成的同一 TC 表；任何上述参数变化会重建 runtime TC，且进入胶片 setup、印相 midgray 和负片缓存 key。

## 资产

`engine.bin` 格式 v4，23,877,324 字节，SHA-256 为 `793208861abbf022e02f2fb09e7b3a5a36a41a1e7f379b0dadd46f4d7a26a46d`。新增源 Hanatos spectra、Mallett basis、可见光谱 locus 与 Oklch Cmax 表。Oklch 的 L/h/Cmax 网格使用 float64，避免 float32 的角度步长累积使 TC 最大误差升高到约 0.00076。manifest 同时记录生成器、源 spectra、basis、locus 和 profiles 的 hash。

## 验证

```powershell
pwsh -NoProfile -File tools/host/run_spectral.ps1
pwsh -NoProfile -File tools/parity/run.ps1 -Cases portra-uv-ir,portra-adaptation-off,portra-surface-blur,portra-mallett,portra-input-gamut-off,portra-input-gamut-oklch,portra-input-gamut-knee -OutputDirectory build/spectral-runtime-parity
```

直接 setup 比较的七个案例，TC 或 Mallett 矩阵最大绝对误差为 1.5388×10⁻⁵；Oklch 的最大误差为 8.5073×10⁻⁷。报告保存到 `build/spectral-input-contract/results.json`。

完整 pipeline 对同七组参数比较 `log_e_film`、`cmy_film`、`log_e_print`、`cmy_print` 和新增 `rgb_out_linear`：density tap 最大绝对误差 8.3447×10⁻⁷，linear RGB 最大绝对误差 4.4703×10⁻⁷，最终 RGB8 最大差异 1 码值，p99 均为 0。报告保存到 `build/spectral-runtime-parity/results.json`，失败数为 0。

输入仍为 Android 解码到的 linear extended sRGB。此验证涵盖 Portra 400 的上述确定性参数，未穷举所有 film/paper 组合，不证明 grain/glare 的随机样本逐像素一致，也不替代设备相机、GPU 录制和性能验证。

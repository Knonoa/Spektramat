# Spektramat 与 spektrafilm / SpektraLab 的算法差距全量梳理

基线版本：Spektramat `e7baa584bf631d64e23e7acc639f81cacbc673ed`；spektrafilm `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`；SpektraLab `1952c63537ec576d24422f1065b12495631346a5`。

本文只讨论图像处理算法、数值路径和默认参数，不讨论相机、图库、导出界面等产品功能。结论按“已经从代码确认”和“需要跨实现测试才能量化”区分。

## 结论

Spektramat 的 full engine 是 spektrafilm 的 C++ 移植，但不是逐像素等价实现。最大差异是：印相和扫描始终先烘焙成 41³ 三维 LUT，而 spektrafilm 默认逐像素执行 81 波长光谱积分；此外 Android 的 full 成片只暴露固定的一组物理参数，缺少参考实现的输入/输出色域、相机滤镜、扩散、预闪、扫描校正和相纸曲线形变等开关。

SpektraLab 当前 Mac 产品的普通路径已经拒绝 enlarger/scanner LUT，使用精确光谱积分；它与 Spektramat 在“相机曝光补偿推动成片亮度”这一产品默认上相同，但在色彩空间、场景曲线、扫描输出和 HDR/EDR 方面更完整。

## 1. 输入、色彩空间与光谱上采样

| 算法项 | spektrafilm | Spektramat | SpektraLab | 差异性质 |
|---|---|---|---|---|
| 输入工作空间 | 默认 ProPhoto RGB；可传 input color space 和 CCTF 解码 | 解码后固定为 scene-linear sRGB；JNI/引擎输出固定 sRGB | 支持 ProPhoto、Adobe RGB、Display P3 等产品色彩空间 | 数值路径不同 |
| RGB→胶片曝光 | Hanatos 2025 或 Mallett 2019 可选 | 只实现 Hanatos 2025 | 原生管线支持参考实现配置，普通产品路径以完整参数为准 | 算法/能力缺失 |
| Hanatos 适配 | window、surface、spectral Gaussian blur 可配置 | `rgb_to_raw()` 直接使用已烘焙 tc 表，没有这些运行时开关 | 继承完整设置和缓存 | 参数缺失 |
| 输入色域压缩 | `input_gamut_compress` 在 tc LUT 生成时生效 | 没有对应输入 gamut compression；超出 sRGB 的输入在进入引擎前已被限制在 Android 解码语义内 | 支持输入色域压缩 | 高饱和输入结果不同 |
| 负值/非有限值 | Python 参考路径按 spectral upsampling 和 `nan_to_num` 规则处理 | `rgb_to_raw()` 只在总亮度和最终曝光处做有限值保护 | 原生实现有独立的输入检查 | 极端输入需 parity 测试 |

证据：Spektramat [engine_image.hpp](../engine/src/main/cpp/engine_image.hpp) 规定 pipeline 输入为 linear sRGB；[spektra_engine.cpp](../engine/src/main/cpp/spektra_engine.cpp) 的 `rgb_to_raw()` 只有 Hanatos 路径。spektrafilm 的 `params_schema.py` 定义 `input_color_space="ProPhoto RGB"`、`input_cctf_decoding`、`mallett2019` 和输入 gamut compression。

## 2. 自动曝光和曝光语义

| 算法项 | spektrafilm | Spektramat | SpektraLab |
|---|---|---|---|
| 测光色彩空间 | 按输入色彩空间转 XYZ/Y，再按 `auto_exposure_method` 测量 | C++ meter 固定使用 linear sRGB 的 luminance weights 和 center-weighted 高斯权重 | 会话在固定 meter tier 测量一次，产品新帧默认 balanced，旧编辑保留兼容语义 |
| 测光方法 | 支持方法字段，不限于 center-weighted | `RenderParams` 没有方法字段，只能 center-weighted | 产品层有更完整的 session meter 语义 |
| 测光时机 | 每次 pipeline process 对当前图像测量 | Android 导入时保存 `meteredEv`；JNI full develop 关闭引擎二次自动曝光，使用保存读数加 UI EV | 会话级缓存，tier 共享同一读数 |
| 曝光补偿 | 先作用于胶片曝光；默认印相 compensation=true 时可抵消成片亮度变化 | full engine 的 `print_exposure_compensation=false`，曝光补偿会改变最终成片亮度；与当前 Mac 产品默认相同 | 产品默认 false；参考 Params 默认 true |

因此同一原片在“重新测光、改变裁切、改变输入色域、改变导入时机”时，Android 与 Python 的曝光可能不同。

## 3. 相机滤镜、增益和空间扩散

spektrafilm 在 `FilmingStage.expose()` 中依次执行高光 boost、相机 diffusion filter、镜头 Gaussian blur、halation。Spektramat 的 `RenderParams` 没有这些独立字段，full C++ 只保留后面的 scatter/halation：

| 参数/阶段 | 参考实现 | Spektramat 当前状态 |
|---|---|---|
| UV band-pass filter | `camera.filter_uv` | 无；没有对应 RenderParams/JNI 映射 |
| IR band-pass filter | `camera.filter_ir` | 无 |
| 高光 boost/protect | `halation.boost_ev`、`boost_range`、`protect_ev` | 无；曝光直接进入 scatter/halation |
| 相机镜头 blur | `camera.lens_blur_um` | 无 |
| 相机 diffusion filter | 完整 PSF 家族、强度、尺寸、暖度和组分权重 | 无 |
| 印相镜头 blur | `enlarger.lens_blur` | 无 |
| 印相 diffusion filter | 完整 PSF | 无 |

这不是单纯默认值差异，而是当前 Android 无法表达这些参考算法。

## 4. 胶片曝光和显影

### 4.1 胶片曲线与 DIR

两者都实现 log exposure → density 曲线、正片/负片方向和 DIR 层间耦合。Spektramat C++ 的基本矩阵和空间扩散结构与参考实现相近，但：

1. Spektramat 将 `inhibition_samelayer`、`inhibition_interlayer` 固定为 1，DIR gamma/矩阵按少数 stock 分支硬编码；参考实现从 `DirCouplersParams` 读取全部系数。
2. Spektramat 将 diffusion size=20 µm、tail=200 µm、tail weight=0.06 固定；参考实现可调。
3. Android UI/JNI 允许 `dir_couplers_amount` 到 2.0，而参考 GUI/参数语义的安全范围约为 0…1.5。外部受控 parity 中，普通参数最大误差为 1 个 8-bit code；`amount=2` 时最大差达到 87，约 12.95% 通道样本差异超过 2。
4. 参考实现支持 `density_curve_gamma`；Spektramat `RenderParams` 没有该字段，等价于固定 1.0。

### 4.2 散射与光晕

Spektramat full engine 确实有散射、三次反射光晕和按胶片 antihalation 标签选择的强度，因此不是“完全没有 halation”。但它把参考实现的可调参数压缩成两个总量：

- `scatter_amount`、`halation_amount` 可调；
- scatter core/tail 半径、tail 权重、halation 首个 sigma、bounce 数、bounce decay、renormalize 固定为 C++ 常量；
- 不支持 `scatter_spatial_scale`、`halation_spatial_scale`、按通道的参数覆盖和高光 boost；
- 只使用 `cine ? 50 µm : 65 µm` 的固定 sigma 规则。

### 4.3 颗粒

Spektramat 保留了分层粒子、Poisson/binomial 采样、染料云和微结构等结构，但与 spektrafilm 不保证同一随机 realization：

- C++ 使用自己的 splitmix/RNG 流；Python 使用其自身随机实现；同一 seed 不能据此要求逐像素相同。
- 粒子面积、三通道尺度、层尺度、uniformity、blur、micro blur/sigma 都在 C++ 固定为常量，不能使用参考参数对象逐项覆盖。
- C++ 对 sublayer 路径硬编码三层处理；参考实现的 `n_sub_layers` 是参数。
- Android 的 `grain_amount` 是额外的 `clean + amount * (grained-clean)` 混合；参考实现的 active/sublayers/粒子模型参数语义不完全相同。

## 5. 印相（enlarger）算法

这是当前最主要的确定性差距。

### 5.1 LUT 与逐像素积分

spektrafilm 的 `PrintingStage._film_cmy_to_print_log_raw()` 默认：

1. 胶片 CMY 密度和 base density 合成为每个波长的 spectral density；
2. 经过 TH-KG3 和中性滤镜；
3. 按 81 波长计算 `density_to_light`；
4. 与相纸 sensitivity 相乘并求和；
5. 乘 midgray geometric-mean normalization。

只有 `settings.use_enlarger_lut=True` 时才使用 LUT。Spektramat 在 `build_print_setup()` 中无条件生成 41×41×41 LUT，`print_stage()` 对每个像素三线性采样。因此 LUT 插值误差、域外夹取和 41³ 采样误差都会进入 full 成片。

### 5.2 默认值和缺失参数

| 项目 | spektrafilm | Spektramat |
|---|---|---|
| enlarger illuminant | 可选名称，默认 TH-KG3 | 固定 TH-KG3 |
| 中性滤镜 | 由数据库和 `y/m/c_filter_neutral` 决定 | 固定基线 c=0、m=65、y=55，再叠加 Y/M shift |
| print exposure compensation | 默认 true | 默认 false；参考 SpektraLab 产品也为 false |
| normalize print exposure | 独立字段 | 没有字段，按固定逻辑使用 midgray factor |
| preflash | 支持 exposure、Y/M shift 和 base density preflash | 无 |
| enlarger lens/diffusion | 支持 | 无 |
| black/white color reference | 参考 ColorReferenceService 会参与 filming、printing、scanning | C++ 只做 midgray exposure factor，没有完整 black/white reference correction |
| 相纸曲线形变 | `density_curves_morph` | 只能使用资源中的固定 print curves |

## 6. 相纸显影与扫描

### 6.1 相纸显影

Spektramat 通过 `paper.print_curves` 做固定插值；spektrafilm 通过 `develop_print_morph()` 支持相纸密度曲线的 morph，并按 profile type 处理。Android 没有 morph、gamma 或化学过程参数。

### 6.2 扫描光谱积分

spektrafilm 默认从相纸/胶片染料密度直接计算 81 波长透射光，再乘 viewing illuminant 和 CIE 1931 CMF，按 Y 归一化得到 XYZ。Spektramat `build_scan_setup()` 同样使用 profile 的 viewing illuminant 和 CMF，但先烘焙为固定 41³ scanner LUT，`scan_stage()` 再三线性采样。

因此“印相 LUT”和“扫描 LUT”是两个独立的近似误差来源；直接扫底片 `scan_film=true` 也仍走 scanner LUT。

### 6.3 扫描后处理

| 项目 | spektrafilm | Spektramat |
|---|---|---|
| scanner lens blur | 可调 | 无 |
| black/white correction | 可调开关、black/white level | 无完整参数 |
| glare | 参数化 percent/roughness/blur | 固定 0.03/0.7/0.5，只对 print scan 生效 |
| unsharp mask | `(sigma, amount)` 可调 | 固定 sigma=0.7、amount=0.7 |
| 输出色域 | 可选 sRGB、Display P3、Adobe RGB、ProPhoto 等 | 固定 linear sRGB 后编码为 sRGB 8-bit |
| output gamut compression | 可选算法和参数 | 固定 CAM16-UCS 压缩实现，不能切换/调参 |
| CCTF | 输出色彩空间可独立决定是否编码 | 固定 sRGB encode，并最终 clamp 到 8-bit |

## 7. 预览、相机和最终成片的算法差距

即使只看 Spektramat 自己，以下路径也不是同一个算法：

1. **Full engine**：包含邻域 scatter、halation、DIR 空间扩散、分层颗粒、glare、scanner unsharp 和 41³ print/scan LUT。
2. **暗房 GPU/缩略图**：`latent.glsl` 使用 film/print/scan 表做 pointwise 计算，明确省略 scatter、DIR 空间扩散、glare 和 scanner sharpening；颗粒是均值/方差表加 PCG 高斯噪声近似。
3. **相机和录像**：把 display-referred sRGB 线性化后走 grade/film/print 表；没有 full halation 多 pass，也不会运行 full engine 的邻域效果。
4. **Sony 监视器**：`Monitor.kt` 明确使用 fast path，关闭 grain 和 halation。
5. **片边/日期 proof**：为生成底片上的片边和日期，改走小尺寸 full engine proof；GPU 普通预览不能代表最终带片边成片。

所以现有 `FAST_VS_ENGINE` 通过，只能说明 Spektramat 的 fast CPU twin 与 Spektramat 自己的 full engine 在受控配置下相符，不能证明 GPU/相机/监视器与 spektrafilm 逐像素一致。

## 8. Spektramat 与 SpektraLab 的算法差距

SpektraLab 当前 Mac native pipeline 在 `pipeline.cpp` 中明确拒绝 enlarger/scanner LUT 配置，普通路径使用精确光谱积分；Spektramat full engine 固定使用 41³ LUT。这是两者的第一项核心差别。

其他已确认差异：

- Spektramat 输入和输出固定 linear/display sRGB；SpektraLab 支持 ProPhoto、Adobe RGB、Display P3 等工作空间。
- SpektraLab 有 scene latitude mapping、HDR/EDR、gain-map 和 slide HDR scan；Spektramat 没有这些处理阶段。
- SpektraLab 暴露 scanner black/white correction、输出色域和更完整的光谱/打印设置；Spektramat 固定 CAM16、unsharp 和 8-bit sRGB 输出。
- SpektraLab 产品默认 `print_exposure_compensation=false`，这一点与 Spektramat 相同；但 spektrafilm reference schema 默认 true。
- SpektraLab 的 grain、halation、glare、scene latitude 等参数在 `Params` 中独立存在；Spektramat 以少量总量控件和固定常量替代。
- SpektraLab 还有 minilab 标定路径（例如 Portra400/Endura），该路径不是 Spektramat 的普通 9 款相纸 LUT 语义，不能把两者的 profile 名称直接视为同一算法。

## 9. 差距优先级

### P0：影响“算法一致性”的核心项

1. full engine 将 41³ enlarger/scanner LUT 替换为逐像素 81 波长积分；LUT 只保留给预览和低延迟路径。
2. 对照 spektrafilm 实现完整 black/white color reference correction。
3. 统一 `print_exposure_compensation`、normalize 和 midgray factor 语义，并在 parity 中明确 reference 默认与 SpektraLab product 默认的差别。
4. 将 DIR amount 限制在参考实现安全范围，至少在 UI、JSON、JNI 和 C++ 入口统一钳制到 1.5。

### P1：影响高光、边缘和空间观感

1. 增加 UV/IR filter、highlight boost/protect、camera/enlarger lens blur 和 diffusion filter。
2. 将 halation/scatter 的 spatial scale、按通道强度、bounce 参数从常量改为 RenderParams。
3. 让 print preflash、print curve morph、scanner lens blur、white/black correction 可传入。
4. 对 GPU 预览补齐或明确标注邻域效果差异。

### P2：影响色彩管理和交付结果

1. 支持 ProPhoto/Display P3/Adobe RGB 输入输出和 CCTF 选择。
2. 接入 input/output gamut compression 的可配置实现。
3. 提供 16-bit/宽色域输出，避免最后固定到 sRGB 8-bit 后再判断 parity。
4. 规划 scene latitude、HDR/EDR 与 gain-map 路径。

## 10. 验证边界

当前已有验证：Spektramat fast CPU twin 与自身 full engine 的 `FAST_VS_ENGINE_FAILURES 0`；受控外部 parity 中普通参数最大差 1 个 8-bit code，DIR amount=2 时最大差 87。

尚未证明：真实 Android GPU、真机 RAW 解码、广色域输入、HDR、Sony 监视器、录像、随机颗粒逐样本一致，以及逐像素 81 波长参考实现替换后的性能/误差。后续 parity 必须固定输入线性 RGB、profile、波长资产、seed、曝光和所有 spatial/stochastic 开关，分别比较 filming、develop、printing、scanning tap，不能只比较最终 8-bit JPEG。

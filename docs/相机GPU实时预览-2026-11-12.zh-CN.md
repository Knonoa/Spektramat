# 手机相机 GPU 实时预览

本轮按确认的规则，将手机拍摄前取景切换为 GPU LUT；拍下的 JPEG/RAW、照片缩略图、暗房、冲印和导出继续使用完整 spektrafilm 算法。Sony USB 非录制监看继续原有完整算法。

## 实现

CameraX 的普通 Preview SurfaceProvider 提供外部相机纹理，OpenGL ES 3 直接绘制到 TextureView。取景不通过 CameraEffect，因此不占用 RAW 不兼容的照片 effect 路径；独立 CameraEffect 仅允许 VIDEO_CAPTURE。

照片取景顺序：encoded sRGB → linear sRGB → 场景调整（不含手动 EV）→ 实时自动曝光 → 对数 shaper → 完整引擎生成的逐像素胶片/印相/扫描 LUT → 整饰 → sRGB 显示。

手动 EV 和印相曝光补偿由生成 LUT 的完整引擎执行一次。自动测光使用参考七种方法，每 250ms 从不含黑边的相机画面读取最长边不超过 256px 的原始 RGBA8 小图；EV 平滑更新并限制到 ±12。自动曝光更新只改变 GPU uniform，不重新生成 LUT。

取景 LUT 使用 97³ RGB32F，约 10.45MiB；shaper 为 `log2(1 + linear * 65536) / 24`，线性输入范围约 0–256，超出范围的预览输入截断。生成时按 4 层分块执行完整引擎，避免一次为整立方体分配所有中间图像。GPU 采用手动三线性插值，不依赖设备的浮点纹理过滤支持。

配方变化后在后台生成新 LUT；生成期间旧配方继续绘制实时画面，首次生成期间显示原始相机画面。界面显示“正在更新胶片预览”。录像开始至 Finalize，取景切换到录像自身的 LUT 和固定曝光规则，与编码输出的处理规则一致。

预览固定为 SDR sRGB。LUT 包含完整逐像素颜色转换，但关闭依赖邻域、随机过程和整图统计的阶段，包括光晕、颗粒、眩光、扩散、镜头/扫描模糊、锐化、扫描黑白参考校正、片边和日期；整饰暗角保留。界面提示“实时预览 · 光晕/颗粒等效果以成片为准”。这些取景限制不改变照片的完整处理。

## 验证与交付

本轮验证通过，历史照片算法基线见 [算法对齐验证](算法对齐验证-2026-11-12.zh-CN.md)。本轮没有重新执行 56 组 Python 参考对照；新增的是实时取景路由与 LUT，不改照片核心算法。

- Host 预览：Portra 默认、手动 EV/滤镜/印相调整、Ektachrome 直扫、HP5 黑白，分别测试自动曝光 −4/0/+4EV，共 12 组。每组以 1,024 个独立随机颜色输入比较完整引擎，门槛为最大 ≤2、RMS ≤0.25 个 8 位色阶。实际最高最大差异 **1.2746**，最高 RMS **0.2093**；七种测光及额外 grade 曝光契约通过。报告：`build/preview-lut-delivery/results.txt`。
- Host 照片路由、曝光一次、印相补偿与缓存契约通过：`build/photo-preview-regression/photo-contract.txt`。原视频四组 LUT 回归通过：`build/video-lut-preview-regression/results.txt`。
- Android arm64-v8a/x86_64 debug 构建与 **23 项 JVM 测试**通过。API31 AVD 的 **9 项 instrumentation 全部通过，0 失败、0 跳过**。
- 实际 CameraX→OES→TextureView 取景测试覆盖非黑画面、3:4/9:16 尺寸、配方更新、照片/视频模式、前后摄和 stop/start；原始 JPEG 归档字节保持不变，完整算法缩略图生成成功。已查看后摄实际取景截图。该模拟器不支持 RAW，因此条件式 RAW 切换分支未执行；硬件 JPEG 捕获受已知 EmulatedFakeCam 编码崩溃限制，使用文件归档验证。
- 编译生产 OES shader，并将同一 shader 的 2D 输入版本与独立 native sampler 比较，包含场景调整、手动 EV 与 −2/0/+2EV 动态曝光。GPU/CPU 最大差异 **1**，最高 RMS **0.0625** 色阶；原视频 GPU/CPU 最大差异 **1**、RMS **0.0360844**。

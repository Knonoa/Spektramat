# Spektramat 与 spektrafilm / SpektraLab 差异分析

日期：2026-11-12
范围：当前 `Spektramat` Android 应用、最新 `spektrafilm` 参考实现、最新 `SpektraLab` 2.3.2。

## 1. 对比版本与方法

本次工作区中的版本如下：

| 项目 | 版本/提交 | 作用 |
|---|---|---|
| Spektramat | `e7baa584`（与 `origin/main` 一致） | Android 应用、C++ 引擎、OpenGL ES 预览 |
| spektrafilm | `3bb2c2d`（远端最新） | Python 光谱参考实现与桌面 GUI |
| SpektraLab | `1952c635`，2.3.2 | macOS/Metal 产品与 C++ 引擎 |

对比依据包括三个仓库的 README、引擎和 UI 源码，以及 Spektramat 的 `tools/host/run.ps1`。该宿主测试覆盖 25 款胶片、GPU/CPU 表路径、颗粒、整饰和片边，结果为 `FAST_VS_ENGINE_FAILURES 0`。

另外用 workspace 中的 parity harness 将 spektrafilm Python runtime 与 Spektramat C++ engine 做了固定参数对比。测试图像为 160×120，曝光范围 −12 到 +6 EV，全色相/饱和度 sweep，并关闭空间和随机效果；再单独测试了曝光、滤镜和 DIR 极端值。

## 2. 结论摘要

Spektramat 沿用了 spektrafilm 的核心暗房模型：

> 场景曝光 → 胶片显影 → 印相或直接扫描 → 扫描输出。

在普通参数范围内，Spektramat 的全尺寸 C++ 成片与 spektrafilm 参考实现基本一致：上述样例中 Portra 400/Endura、Ektachrome 100 直接扫描、HP5/Multigrade、Vision3 500T/2383 以及曝光和 Y/M 滤镜变化，最大通道差为 1 个 8-bit code。

主要差异来自移动端性能和产品范围，而不是另一个色彩模型：Android 使用预烘焙资产、41³ 印相/扫描 LUT、线性 sRGB 输入和 RGBA8 sRGB 输出；全尺寸成片才运行邻域型散射、DIR 扩散和随机颗粒模型，GPU 预览采用近似。Spektramat 当前最明确的数值边界是 DIR 耦合滑杆可到 200%，而 SpektraLab UI 将该值限制在 0…1.5；在 `dir_couplers_amount=2` 的 parity 中最大差为 87 code，p99 为 52 code，约 12.95% 通道样本超过 2 code。

产品层面，Spektramat 把参考引擎包装成 Android 相册、相机、录像、Sony USB 监视器、卷式片库、后台冲印和移动灯箱。SpektraLab 的目录、评级、变体、Capture One 只读目录、HDR/EDR、多色彩空间和 16 位导出目前不在 Android 版本中；Android 则增加了手机相机、录像、Sony tethering 和移动端工作流。

## 3. 算法差异

### 3.1 胶片曝光、色彩和输出

| 环节 | 最新 spektrafilm | Spektramat |
|---|---|---|
| 胶片曝光模型 | 可选择 Hanatos2025、Mallett2019 等实现 | 运行时固定 Hanatos2025；资产中预烘焙 192² `tc_lut`，使用 fp16 资源 |
| 输入 | 线性图像，可配相机色彩、曝光和工作色域 | 导入后转 scene-linear sRGB（DNG 由 LibRaw/自有解码路径处理） |
| 胶片/相纸光谱积分 | 参考实现默认可直接进行 81 波长积分，也可选择 LUT | 印相和扫描固定使用 41³ LUT，并在 C++ 中三线性插值；见 `engine/src/main/cpp/spektra_engine.cpp` 的 `kLut3dN`、`print_stage`、`scan_stage` |
| 输出 | 可选 sRGB、Adobe RGB、Display P3、ProPhoto 等色彩空间和显示配置 | CAM16 色域压缩后固定编码为 RGBA8 sRGB；没有 Android UI 的色彩空间导出选择 |
| 自动曝光 | 每次处理可配置 metering/auto-exposure | 导入时做一次中心加权测光，成片 JNI 明确把 `auto_exposure` 关闭，曝光滑杆在测光值上加减 |
| 直接扫描 | 可配置扫描参数和色彩工作流 | `scan_film` 分支保留，但输出仍走移动端固定 sRGB/锐化路径 |

SpektraLab 的 C++/Metal 引擎也源自 spektrafilm，并保留全分辨率光谱流程；Android C++ 引擎是针对手机内存、启动时间和实时预览做的移植与资产化实现。

### 3.2 光晕、散射和 DIR 成色剂

- spektrafilm 暴露散射核心/尾部、空间尺度、反射/多次反弹、halation 强度等参数。
- Spektramat 全尺寸成片保留这些模型，但 Android `Look` UI 主要给出光晕总量；散射与光晕共用控制，不能像参考实现一样分别调所有参数。
- Spektramat 全尺寸成片的 DIR 仍使用当前像素以外的扩散核（默认 diffusion/tail 参数在 C++ 中定义）；GPU 预览的 `latent.glsl` 只用当前像素，省略空间扩散。
- Spektramat UI 将层间效应/`dir_couplers_amount` 放宽到 0…200%。SpektraLab 的 `FilmParams.swift` 将 coupler 限制为 0…1.5；应把 Android 上限收紧到 150% 或更保守的范围。

### 3.3 颗粒

- spektrafilm 和 Spektramat 全尺寸成片使用 Poisson/binomial 颗粒采样，可选多层乳剂、染料云和微结构，并按底片画幅的微米尺度计算。
- Spektramat GPU 预览为了实时性使用预计算均值/方差表加高斯噪声（`latent.glsl` 的 `film_grain`），不运行完整随机粒子和邻域模型。预览与最终成片的颗粒纹理因此不会逐像素相同。
- 预计算表在 `lt_tables.cpp` 中从引擎的颗粒模型生成，既保留密度相关方差，也保留均值偏置；它是统计近似，不是简化成固定强度噪声。
- SpektraLab 产品资源对黑白 stock 另有单层颗粒/标定约束；其 `channel_model` 为 `"bw"`，仍使用三通道容器，并非独立的单通道渲染器。Spektramat 目前没有等价的 stock-grain calibration UI，建议补齐黑白配置说明和校准数据。

### 3.4 放大机、扫描和锐化

- Spektramat 暴露印相曝光、Y/M 滤镜和直接扫描开关；没有 spektrafilm/SpektraLab 中完整的预闪、乳剂散射独立控制、扫描黑白点校正和可调锐化面板。
- 全尺寸扫描阶段仍有固定 unsharp mask；UI 没有关闭或调节该参数的入口。
- 相纸/扫描的 LUT 由 41³ 网格承载；普通范围内 parity 的 1 code 误差表明该网格对常规曝光足够，但高饱和/极端曝光和自定义 profile 仍应单独做 QA。

### 3.5 GPU 预览与全尺寸成片

| 场景 | 实际路径 | 与 spektrafilm 的差异 |
|---|---|---|
| 暗房 GPU 预览 | OpenGL ES 3、胶片/印相 LUT、预计算颗粒统计、最长边约 512 的单高斯光晕缓冲 | 省略 DIR 空间扩散；颗粒为统计近似；光晕为单高斯近似 |
| Android 相机取景/录像 | 外部相机纹理，经 `Programs.kt` 胶片表和整饰表 | 为帧率没有光晕，也没有完整邻域效果；监视器同样明确关闭颗粒和光晕 |
| 全尺寸冲印 | JNI 调用 C++ engine，按完整流程输出 JPEG/MediaStore | 运行完整颗粒、光晕、DIR、眩光和扫描锐化；与参考实现做 parity |

因此 UI 中的“实时胶片效果”应理解为预览近似；需要判断光晕、DIR、颗粒细节时，应以后台全尺寸成片为准。

## 4. 数值 parity 结果

| 测试 | 结果 |
|---|---|
| Portra 400 / Endura，−12…+6 EV sweep | 最大差 1 code |
| Ektachrome 100 直接扫描 | 最大差 1 code |
| HP5 / Multigrade | 最大差 1 code |
| Vision3 500T / 2383 | 最大差 1 code |
| Portra，曝光/Y/M 滤镜/印相曝光变化 | 最大差 1 code |
| DIR coupler amount = 2 | 最大差 87，p99 = 52；12.95% 样本差异 >2 code |

DIR 极端值差异不是普通曝光下的 LUT 精度问题，而是参考曲线反演轴在约 1.736 以上失去单调性；SpektraLab UI 已通过 1.5 上限避开该区域。Spektramat 应限制 UI 输入，并在 JNI/引擎层再次 clamp，避免配方或旧 JSON 绕过 UI。

## 6. 验证状态与复现性

已通过：

- `Spektramat/tools/host/run.ps1`：`FAST_VS_ENGINE_FAILURES 0`。
- C++ engine 与 spektrafilm 参考实现的普通参数 parity（最大 1 code）。
- PTP 收发和 Sony 数据解析单元测试（分包、空包、截断、越限、错误码共 13 项）。

尚未通过真机验证：

- Sony 相机 USB 握手、实时取景对象号、遥控快门和收片流程；当前使用演示相机走通 UI。
- 手机闪光灯、系统相机回传、拍下即冲印。
- Android 13+ 玻璃放大镜在真实硬件上的 GPU 表现。

批量冲印队列目前驻留内存，应用重启后不会续跑；联机暂存原片/录像会在下次启动时自动补登记。该差异应在产品文档中明确，避免与 SpektraLab 的逐张批量导出恢复能力混淆。

另外，Spektramat 源码注释引用 `tools/bake_assets.py` 和 parity 工具，但仓库内当前 `Spektramat/tools` 只有 `tools/host/run.ps1` 与 `tools/host/fast_vs_engine.cpp`；资产生成和 Python parity 工具在 workspace 外层 `F:\LocalProject\SpektraLab\tools`。若要让第三方复现 APK 或重新生成 profile，应把工具纳入仓库，或记录工具所在提交、输入 profile 版本和生成命令。

## 7. 优先级建议

1. **P0：限制 DIR 耦合范围。** UI、JSON 读取和 JNI 三层均 clamp 到不超过 1.5，并为旧配方写迁移提示；补一个 `amount=1.5/1.736/2.0` 的回归测试。
2. **P1：标注预览与成片差异。** 在光晕、DIR、颗粒控件旁说明实时预览采用近似，最终效果以全尺寸冲印为准；监视器/录像页面说明不含颗粒和光晕。
3. **P1：固定资产和 parity 复现链。** 将 `bake_assets.py`、profile manifest 和 parity harness 纳入仓库，或在 `docs/开发.md` 写出固定提交及生成校验和；把 Android engine 对 spektrafilm 的常规 profile parity 加入 CI。
4. **P2：补齐黑白颗粒校准。** 采用 SpektraLab 的 `channel_model="bw"` 约束和 stock-grain 标定数据，至少在黑白片配方中显示当前颗粒模型限制。
5. **P2：补齐导出和图库能力。** 根据目标用户优先级增加 16 位 TIFF/HEIF、Display P3/Adobe RGB、评级/色标/变体，以及可恢复的批量冲印队列。
6. **P3：扩展移动端编辑。** 自由裁切、拉直、透视校正、通道混合器和半格双图拼接可作为后续产品功能，不影响当前引擎 parity。
